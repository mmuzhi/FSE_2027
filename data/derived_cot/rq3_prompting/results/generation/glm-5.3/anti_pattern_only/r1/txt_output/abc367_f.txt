This is a classic problem: given two arrays A and B, and queries asking whether the multiset of A[l..r] equals the multiset of B[L..R].

The standard approach is hashing: assign a random value to each distinct integer (1..N), then compute prefix hashes of sums of random values (or better, use a hash that's robust). Since multiset equality can be checked by comparing sums of random values assigned to each element — with random values from a large range, collisions are unlikely.

Wait, but sums alone can collide easily? Let's think. Assign to each value v in [1,N] a random 64-bit integer h(v). Then the hash of a multiset is sum of h(x) for x in the multiset. Two different multisets collide only if the difference of the character sums equals zero. The difference is a linear combination sum c_v * h(v) where c_v are integers bounded by the length of the interval (up to 2*10^5 in absolute value... actually c_v = count in A interval minus count in B interval, |c_v| ≤ N). Looking at this problem: I need to check multiset equality of two subarrays for each query. The standard approach is randomized hashing — assign each distinct value in `[1, N]` a random 64-bit integer, and compare prefix sums of these random values over the ranges.

Two different multisets produce equal sums only if a non-trivial integer linear combination of random values equals zero; fixing all random values except one shows this happens with probability at most 2⁻⁶⁴ per mismatching query. With Q ≤ 2×10⁵ fixed (non-adaptive) queries, total failure probability is ~10⁻¹⁴ — negligible. I also check that the two ranges have equal length first (necessary for multiset equality, and cheap).

Using Python's arbitrary-precision integers means no overflow issues with sums of 64-bit values. Prefix sums are built with `itertools.accumulate` (C-speed), and queries are processed by grouping the flat token iterator in fours with `zip(it, it, it, it)`.

Verification against samples:
- Sample 1: lengths check catches query 2; hash equality correctly identifies queries 1 and 4 as Yes, query 3 as No. ✓
- Sample 2: all elements are 4, so prefix sums are multiples of the same random value; length checks catch queries 3 and 4. ✓

    rnd = [0] + [gen.getrandbits(64) for _ in range(n)]

    ha = [0] + list(accumulate(map(rnd.__getitem__, A)))
    hb = [0] + list(accumulate(map(rnd.__getitem__, B)))

    it = iter(map(int, data[2 + 2 * n:2 + 2 * n + 4 * q]))
    out = []
    app = out.append
    for l, r, L, R in zip(it, it, it, it):
        if r - l == R - L and ha[r] - ha[l - 1] == hb[R] - hb[L - 1]:
            app("Yes")
        else:
            app("No")
    print("\n".join(out))

main()
