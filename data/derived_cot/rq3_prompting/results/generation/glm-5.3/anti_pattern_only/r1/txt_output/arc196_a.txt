import heapq

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    A = list(map(int, data[1:1 + n]))

    if n % 2 == 0:
        B = sorted(A)
        h = n // 2
        print(sum(B[h:]) - sum(B[:h]))

    lo = []          # max-heap (negated): bottom half

    sum_lo = 0

            z = A[idx]
            if not hi or z >= hi[0]:

                sum_lo += z

            sum_hi -= v

Looking at this problem:

**Key insight**: Each operation pairs two elements (contributing larger − smaller), and the induced pairing on original positions is non-crossing, with no pair spanning the final leftover element.

**Claim**: For any contiguous block of even length L, the max score to clear it completely equals (sum of top L/2 values) − (sum of bottom L/2 values). 
- *Upper bound*: pairs partition the block; total = Σ(designated larger) − Σ(designated smaller) ≤ top half − bottom half.
- *Achievable*: color top-half values red, bottom-half blue (every red ≥ every blue). Repeatedly remove any adjacent red-blue pair (always exists while both colors remain). Each removal scores red − blue, total = top half − bottom half.

So:
- **Even N**: answer = sum of top N/2 − sum of bottom N/2.
- **Odd N**: exactly one element remains at position p (odd index, 1-based); pairs stay strictly within each side. Answer = max over valid p of P(p−1) + S(p+1), where P/S are the block-clearing values for prefixes/suffixes, computed incrementally with two heaps (maintaining top-half/bottom-half sums).

Verified against all samples (e.g., sample 2: leftover at position 1 gives suffix [1,4,1,5,9,2] → (9+5+4)−(1+1+2)=14) and several hand brute-forced cases (e.g., [1,2,100,2,1] → 99, showing position constraints matter).
