class Solution:
    def maximumSubarrayXor(self, nums, queries):
        n = len(nums)
        q = len(queries)
        ans = [0] * q
        # group queries by length
        from collections import defaultdict
        by_len = defaultdict(list)
        for i, (l, r) in enumerate(queries):
            by_len[r - l].append((l, i))

from operator import xor

class Solution:
    def maximumSubarrayXor(self, nums: List[int], queries: List[List[int]]) -> List[int]:

        ans = [0] * len(queries)

        # Group queries by their span d = r - l (processed offline as d grows).
        by_len = {}

Looking at this problem:

**Key insight 1:** The score of subarray `nums[l..r]` satisfies the Pascal-like recurrence `f(l,r) = f(l,r-1) ^ f(l+1,r)` (since the reduction coefficients are binomial coefficients mod 2). Base case `f(l,l) = nums[l]`.

**Key insight 2:** Let `M(l,r)` = max score over all subarrays within `[l,r]`. Any subarray of `[l,r]` is either `[l,r]` itself, inside `[l,r-1]`, or inside `[l+1,r]`, so `M(l,r) = max(M(l,r-1), M(l+1,r), f(l,r))`.

**Algorithm:** Compute `f` and `M` as rolling arrays over increasing span `d = r-l` (O(n²) total), answering queries offline grouped by span — O(q) extra. Answering a query `(l,r)` is just `M[l]` at span `r-l`.

I verified this against both examples (e.g., for `nums=[0,7,3,2,8,5,1]`, at span 3, `M[0]=7`; at span 4, `M[1]=M[2]=14`; at span 1, `M[5]=5` — matching `[7,14,11,14,5]`).

Using `map` with `operator.xor`/`max` keeps the ~2·n²/2 ≈ 2M element operations fast in pure Python.
