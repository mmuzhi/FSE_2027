We have an undirected graph with N vertices, starting with 0 edges. We process Q queries:
- Type 1: add edge between u and v (with u < v, so no self-loops; parallel edges could exist? Possibly, but union-find handles that naturally).
- Type 2: print the k-th largest vertex number among vertices connected to v (including v itself), where k ≤ 10. If fewer than k vertices, print -1.

This is a classic union-find problem where each component maintains a sorted list of its top-10 largest vertex numbers (or we could maintain a full sorted structure).

Approach: Union-Find with "small to large" merging. Each root maintains a sorted list (descending) of the top 10 largest vertices in its component. When merging two components, merge their top-10 lists and keep only the top 10.

For a Type 2 query, find the root of v, look at the list, and if len(list) < k, print -1, else print list[k-1].

Wait, but we need to be careful: the list only stores top 10. If the component size is less than 10, the list contains all vertices. If size ≥ 10, the list contains the top 10. Since k ≤ 10, this works: if component size < k, then list size = component size < k, so -1. Otherwise, list has min(10, size) ≥ k elements (if size ≥ 10, list has 10 ≥ k elements), and the k-th largest is list[k-1].

Merging: when we union two components with lists A and B (each sorted descending, size ≤ 10), merge them into a list of size ≤ 10 by taking the top 10 elements of the merged sorted list. Since each list is ≤ 10, merged is ≤ 20, we can just concatenate, sort descending, take first 10. That's O(20 log 20) per union, and there are at most N-1 effective unions (plus failed ones which are O(1)). Actually Q unions max, but only N-1 successful merges. So total time is fine.

Actually, even simpler: we don't even need small-to-large since each component just keeps top 10. When merging, combine the two top-10 lists and truncate to 10. That's O(1) per union effectively (constant work). 

Union-Find with path compression and union by size/rank: O(α(N)) per operation.

def main():
    input = sys.stdin.buffer.read().split()
    idx = 0
    N = int(input[idx]); idx += 1
    Q = int(input[idx]); idx += 1
    
    parent = list(range(N + 1))
    size = [1] * (N + 1)
    # top[i]: sorted list (descending) of top 10 vertices in component rooted at i
    top = [[i] for i in range(N + 1)]

            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    
    out = []

=== ANSWER ===
Looking at this problem:

- It's a classic **Union-Find** problem where each component needs to answer "k-th largest vertex number" queries with k ≤ 10.
- Key insight: each component's root only needs to maintain a **sorted list of its top-10 largest vertex numbers**. When merging two components, the top-10 of the merged set is contained in the union of the two top-10 lists (≤ 20 elements), so we just concatenate, sort, and truncate to 10.
- For a Type 2 query: if the list has fewer than k elements (which equals component size when size < 10, and is 10 otherwise), print -1; otherwise print list[k-1] (list sorted descending).

I verified this logic against both sample inputs by hand-tracing (e.g., sample 1: after all unions, component of 1 has list [4,3,2,1], giving answers 4, 2, -1 — matching).

Complexity: O(Q·α(N)) for union-find operations plus O(20 log 20) per successful union — easily fast enough for N, Q ≤ 2×10⁵. I use path halving and union by size, with all input read at once for speed.
