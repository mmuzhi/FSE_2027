=== ANSWER ===
Looking at this problem:

- In the augmented string `t = '1' + s + '1'`, runs alternate between 1-runs and 0-runs (first and last runs are 1's).
- Step 1 must zero an **entire interior maximal 1-run** (a sub-block of 1's surrounded by 0's is necessarily a full run with 0-runs on both sides).
- Step 2 must fill an **entire maximal 0-run** of the post-step-1 string (a sub-block of 0's surrounded by 1's must be a full run).
- After zeroing an interior 1-run, the adjacent 0-runs merge with it. Filling that merged run gains `a + b` (lengths of the two adjacent zero runs), since the zeroed 1's are restored.
- Filling some *other* zero run instead gains `M - L` (M = run filled, L = 1-run zeroed). But any zero run (when more than one exists) is adjacent to some interior 1-run R, and trading R with merge gives `≥ M + 1 > M - L`, so the merge strategy always dominates.

Therefore the answer is `ones(s) + max(0, max sum of two consecutive zero-run lengths in t)`, where consecutive zero runs are separated by exactly one interior 1-run.

Verified against all four examples:
- `"01"` → zero runs `[1]`, no pair → 1 ✓
- `"0100"` → runs `[1,2]` → 1+3=4 ✓
- `"1000100"` → runs `[3,2]` → 2+5=7 ✓
- `"01010"` → runs `[1,1,1]` → 2+2=4 ✓
