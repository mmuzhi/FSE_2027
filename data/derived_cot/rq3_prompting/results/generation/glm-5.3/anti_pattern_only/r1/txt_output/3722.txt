=== ANSWER ===
Looking at this problem:

- Let `P` be prefix sums. Define `dp[j][i]` = max sum of exactly `j` non-overlapping subarrays (each length ≥ m) within the first `i` elements.
- Transition: either element `i-1` is unused (`dp[j][i-1]`), or the last subarray ends at `i-1` starting at some `s ≤ i-m`: `dp[j-1][s] + P[i] - P[s]`.
- So `dp[j][i] = max(dp[j][i-1], P[i] + max_{s≤i-m}(dp[j-1][s] - P[s]))`, which is a prefix-max over `s`, then a prefix-max over `i` — both computable with `accumulate`.

I verified this against both examples (13 and -10) and edge cases like all-negative arrays with forced selections. Complexity is O(k·n), fully vectorized with `map`/`accumulate` for speed (worst case n=2000, k=2000 → ~4M light C-level ops).

```python
from typing import List
from itertools import accumulate
from operator import sub, add

class Solution:
    def maxSum(self, nums: List[int], k: int, m: int) -> int:
        n = len(nums)
        P = [0] + list(accumulate(nums))
        
        NEG = float('-inf')
        # prev[i] = dp[j-1][i]: best sum with j-1 subarrays in first i elements
        prev = [0] * (n + 1)  # j = 0: sum 0 for any prefix
        
        for _ in range(k):
            # M[t] = max over 0 <= s <= t of (prev[s] - P[s])
            M = list(accumulate(map(sub, prev, P), max))
            # C[t] = P[m + t] + M[t]: best value when the j-th subarray
            # ends at index m+t-1 (covers first m+t elements)
            C = list(map(add, P[m:], M))
            # prefix max gives dp[j][i] for i >= m (option of not extending)
            Cmax = list(accumulate(C, max))
            # dp[j][i] = -inf for i < m (can't fit a subarray)
            prev = [NEG] * m + Cmax
        
        return prev[n]
```
