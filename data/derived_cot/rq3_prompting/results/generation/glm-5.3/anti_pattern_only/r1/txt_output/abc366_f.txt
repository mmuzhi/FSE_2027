import sys
from collections import Counter
from math import gcd

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0]); k = int(data[1])
    vals = data[2:2 + 2 * n]
    # build counter of (a,b) pairs
    counter = Counter()
    for i in range(n):
        a = int(vals[2 * i]); b = int(vals[2 * i + 1])
        counter[(a, b)] += 1
    # exact sort key: ratio (a-1)/b -> integer key (a-1) * (L // b)

    for i in range(1, 51):

        key = (a - 1) * (L // b)

Looking at this problem:

**Key insight (exchange argument):** For the composition value V = B_{p₁} + A_{p₁}B_{p₂} + ... + A_{p₁}···A_{p_{K-1}}B_{p_K} + A_{p₁}···A_{p_K}, swapping two adjacent functions (outer u, inner v) changes value by P·[B_v(A_u−1) − B_u(A_v−1)]. So the optimal order for any fixed set sorts by ratio (A−1)/B **descending from outermost to innermost** (all B>0 here).

**DP:** Sort all functions by ratio (A−1)/B **ascending**, build the composition from innermost to outermost. Since every function is increasing (A≥1), a larger intermediate value is always at least as good. Knapsack-style DP: `dp[j]` = best value composing j functions as a subsequence processed so far; wrapping a new function gives `A·dp[j-1] + B`.

**Reduction:** Since A,B ∈ [1,50], there are ≤2500 distinct pairs; any solution uses ≤K copies of each pair, and elements with equal ratio can be reordered freely without changing value. So keep only `min(count, K)` copies per distinct pair — at most 25000 items, making the DP at most ~250K operations.
