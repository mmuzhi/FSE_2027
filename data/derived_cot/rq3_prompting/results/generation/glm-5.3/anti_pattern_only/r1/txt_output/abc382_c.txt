=== ANSWER ===
Looking at this problem:

- For sushi j with deliciousness B_j, the answer is the **smallest index i** such that A_i ≤ B_j (the sushi passes people in order 1..N, and the first person whose gourmet level is ≤ the sushi's deliciousness takes it).
- If no such person exists, output -1.

**Approach:** Precompute `first[v]` = smallest person index i with A_i ≤ v, for all v up to 2×10⁵. This is done by:
1. For each value v, record the smallest index of a person with A_i = v (iterate people from last to first, overwriting).
2. Take a prefix minimum over values 0..200000.

Then each query B_j is answered in O(1): `first[B_j]`, or -1 if it exceeds N.

**Verification with Sample 1:** A = [3,8,2]. minIdx[2]=3, minIdx[3]=1, minIdx[8]=2. Prefix mins: first[1]=∞→-1, first[2]=3, first[5]=1. Matches output "1, 3, -1". ✓

**Sample 3 check:** B=70 → first person with A≤70 is person 1 (A=60). B=39 → person 7 (A=37). B=52 → person 4 (A=45). B=33 → person 10 (A=22). B=18 → none, -1. All match. ✓

Complexity: O(N + M + maxV), well within limits.
