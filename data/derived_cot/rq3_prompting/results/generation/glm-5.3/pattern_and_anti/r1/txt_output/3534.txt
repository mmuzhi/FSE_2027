class Solution:

Looking at this problem:

- Constraints are tiny: n ≤ 100, values ≤ 10^6 (at most 7 digits). So a brute-force pairwise check works: for each number, generate the set of all values reachable with at most one digit swap (including itself for zero swaps), converting to int so leading zeros collapse naturally (e.g., "03" → 3).
- Key edge case: the relation must be checked in both directions. E.g., x=3, y=30: swapping digits of 30 yields 3, but no swap of 3 yields 30 — so checking only `nums[j] in variants(nums[i])` misses this pair. The check must be `nums[j] in vs[i] or nums[i] in vs[j]`.
- Each number has ≤ 7 digits → ≤ 21 swap variants, so precomputation is trivial and the pair check is O(1) set lookup.
