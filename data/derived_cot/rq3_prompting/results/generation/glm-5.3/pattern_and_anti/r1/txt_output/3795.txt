```python
class Solution:
    def minZeroArray(self, nums: List[int], queries: List[List[int]]) -> int:
        n = len(nums)
        
        def ok(k):
            diff = [0] * (n + 1)
            for l, r, v in queries[:k]:
                diff[l] += v
                diff[r + 1] -= v
            cur = 0
            for i in range(n):
                cur += diff[i]
                if cur < nums[i]:
                    return False
            return True
        
        lo, hi = 0, len(queries)
        if ok(0):
            return 0
        if not ok(len(queries)):
            return -1
        # binary search smallest k with ok(k)
        lo, hi = 1, len(queries)
        while lo < hi:
            mid = (lo + hi) // 2
            if ok(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo if ok(lo) else -1
```

```python
    def minZeroArray(self, nums: List[int], queries: List[List[int]]) -> int:
        n, m = len(nums), len(queries)

                diff[r + 1] -= v
            run = 0
            for i in range(n):
                run += diff[i]
                if run < nums[i]:
                    return False
            return True

            mid = (lo + hi) // 2
            if feasible(mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
```

Looking at this problem (LC 3356 "Zero Array Transformation II"):

- **Key invariant**: For a fixed prefix of k queries, feasibility is monotone in k — adding another query only adds more optional decrement capacity per index. So binary search on k works.
- **Feasibility check**: For each index i, the total `val` of the first k queries covering i must be at least `nums[i]` (since we can freely choose subsets per query, coverage per index is independent). Compute coverage in O(n + k) with a difference array.
- **Edge cases**: k = 0 (nums already all zeros → 0); if not feasible with all m queries → -1.

Verified against all four examples (answers 2, -1, 4, 4 all reproduced by the check: e.g., example 4 at k=4 gives coverages [2,4,3,2,6] ≥ [1,2,3,2,6], while k=3 fails index 4 with 2 < 6).
