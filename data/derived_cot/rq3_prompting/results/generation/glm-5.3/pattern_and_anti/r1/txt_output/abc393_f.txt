We have a sequence A of length N. For each query (R, X), we want the length of the longest strictly increasing subsequence of A[1..R] using only elements ≤ X.

Standard approach: offline processing. Sort queries by R. Process elements one by one, maintaining a "LIS tail array" (the standard patience sorting array `tails` where tails[k] = smallest possible tail of an increasing subsequence of length k+1 among elements processed so far).

Key observation: When we process element A_i, the LIS state updates: find the first position where tails[pos] >= A_i, replace tails[pos] with A_i (strictly increasing). If A_i is greater than all tails, append it.

Why does this work for the "prefix" part? Because the tails array after processing prefix of length R correctly represents the LIS state for that prefix.

Now for the X constraint: the answer for query (R, X) is the number of tails entries that are ≤ X. Why? The tails array is sorted (increasing). tails[k] is the minimum possible last element of an increasing subsequence of length k+1 in the prefix. If tails[k] ≤ X, then there exists an increasing subsequence of length k+1 with all elements... wait, do all elements need to be ≤ X? The subsequence's last element is tails[k] ≤ X, and since it's increasing, all elements are ≤ tails[k] ≤ X. So yes! If the minimal tail for length k+1 is ≤ X, we can achieve length k+1 with all elements ≤ X. Conversely, if we can achieve length k+1 with all elements ≤ X, then the minimal tail tails[k] ≤ (that subsequence's last element) ≤ X.

So the answer is the number of indices k with tails[k] ≤ X, which can be found by binary search on the sorted tails array.

def main():

=== ANSWER ===
**Approach:** Process elements left to right (offline, queries grouped by R), maintaining the classic LIS "tails" array where `tails[k]` = smallest possible last element of a strictly increasing subsequence of length k+1 in the prefix processed so far. Since the tails array is sorted and strictly increasing, for query (R, X) the answer is simply the number of tails entries ≤ X (any increasing subsequence ending in `tails[k] ≤ X` has all elements ≤ X, and conversely). Update uses `bisect_left` (strict LIS); query uses `bisect_right`.

Complexity: O((N+Q) log N).

Verified against both samples (e.g., after prefix 5 of sample 1, tails=[1,3], so X=2 → 1, X=3 → 2).
