You will be given a competitive programming problem.
You are given a string S of length N consisting of 0 and 1.
Move the K-th 1-block from the beginning in S to immediately after the (K-1)-th 1-block, and print the resulting string.
It is guaranteed that S contains at least K 1-blocks.
Here is a more precise description.

- Let S_{l\ldots r} denote the substring of S from the l-th character through the r-th character.
- We define a substring S_{l\ldots r} of S to be a 1-block if it satisfies all of the following conditions:
- S_l = S_{l+1} = \cdots = S_r =  1
- l = 1 or S_{l-1} =  0
- r = N or S_{r+1} =  0


- 
Suppose that all 1-blocks in S are S_{l_1\ldots r_1}, \ldots, S_{l_m\ldots r_m}, where l_1 < l_2 < \cdots < l_m.
Then, we define the length N string T, obtained by moving the K-th 1-block to immediately after the (K-1)-th 1-block, as follows:

- T_i = S_i for 1 \leq i \leq r_{K-1}
- T_i =  1 for r_{K-1} + 1 \leq i \leq r_{K-1} + (r_K - l_K) + 1
- T_i =  0 for r_{K-1} + (r_K - l_K) + 2 \leq i \leq r_K
- T_i = S_i for r_K + 1 \leq i \leq N

Input

The input is given from Standard Input in the following format:
N K
S

Output

Print the answer.

Constraints


- 1 \leq N \leq 5 \times 10^5
- S is a string of length N consisting of 0 and 1.
- 2 \leq K
- S contains at least K 1-blocks.

=== ANSWER ===
**Approach:** Find all maximal 1-blocks in a single pass (via `split('0')` with position tracking). Let `(l_{K-1}, r_{K-1})` and `(l_K, r_K)` be the (K−1)-th and K-th blocks (0-indexed). The answer is:

- keep `S[0..r_{K-1}]` unchanged,
- place the K-th block (length `r_K - l_K + 1`) right after `r_{K-1}`,
- fill the remaining `l_K - r_{K-1} - 1` positions of the gap with zeros (exactly the zeros that were between the two blocks, preserving total length),
- keep `S[r_K+1..]` unchanged.

**Invariant check:** the span between `r_{K-1}` and `r_K` originally holds `(l_K - r_{K-1} - 1)` zeros plus the block of length `(r_K - l_K + 1)`; the move just reorders them within that span, so total length and the tail are preserved — matching the formal definition.

**Verification on samples:**
- Sample 1: blocks `(1,1),(4,6),(10,11),(14,14)`, K=3 → `"0100111" + "11" + "000" + "001"` = `010011111000001` ✓
- Sample 2: blocks `(0,0),(2,9)`, K=2 → `"1" + "11111111" + "0"` = `1111111110` ✓ (adjacent blocks and block-at-end edge cases both handled: empty tail slice, zero count possibly 0).

Complexity is O(N), well within limits for N ≤ 5×10⁵. Since K ≥ 2 and at least K blocks exist, indexing `blocks[k-2]` and `blocks[k-1]` is always safe.

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    k = int(data[1])
    s = data[2].decode()

    # Find all 1-blocks (l, r) 0-indexed inclusive
    blocks = []
    pos = 0
    for part in s.split('0'):
        if part:
            blocks.append((pos, pos + len(part) - 1))
        pos += len(part) + 1

    r_prev = blocks[k - 2][1]          # end of (K-1)-th block
    l_k, r_k = blocks[k - 1]           # K-th block

    ans = (
        s[:r_prev + 1]
        + '1' * (r_k - l_k + 1)
        + '0' * (l_k - r_prev - 1)
        + s[r_k + 1:]
    )
    print(ans)

main()
```
