=== ANSWER ===
Looking at this problem:

**Key insight:** When k increases by 1, every element increases by 1 except those currently equal to M-1, which wrap to 0. If no elements wrapped, inversions are unchanged. Only pairs involving wrapping elements change:

- Pair (i in W, j not in W), i<j: was inversion (M-1 > anything), becomes non-inversion (0 < anything) → change -1 per pair.
- Pair (i not in W, j in W), i<j: was non-inversion, becomes inversion (B_i+1 > 0) → change +1 per pair.

For wrapping positions p_1 < ... < p_w (1-indexed), summing gives:

delta = Σ_t [ (p_t-1)-(t-1) ] − Σ_t [ (N-p_t)-(w-t) ] = 2·Σp − w(w+1) − w(N−w)

where v = (M−k) mod M is the value wrapping at step k (elements with A_i = v).

**Plan:** Compute inversions for k=0 with a Fenwick tree (O(N log N)), precompute count and position-sum per value, then roll forward for all k in O(M). Verified against all three samples (e.g. sample 2: k=0 gives 7; v=5 has w=2, Σp=4, delta = 8−6−6 = −4 → 3 ✓; all subsequent steps match).

Edge cases: M=1 (single line, 0 inversions since all values 0); equal values don't count as inversions (query prefix up to a+1 counts ≤ a, so previous strictly-greater = idx − s).
