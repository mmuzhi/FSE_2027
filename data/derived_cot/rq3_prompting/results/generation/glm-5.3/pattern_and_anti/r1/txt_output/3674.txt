Return the number of subarrays that you can make non-decreasing ​​​​​after performing at most k operations.
An array is said to be non-decreasing if each element is greater than or equal to its previous element, if it exists.

class Solution:
    def countNonDecreasingSubarrays(self, nums: List[int], k: int) -> int:
        rev = nums[::-1]
        n = len(rev)
        ans = 0
        I = 0
        stack = []  # (value, length), values strictly decreasing bottom->top
        total = 0   # sum of M(j) over window [I, J]
        wsum = 0    # sum of rev[I..J]
        for J in range(n):
            x = rev[J]
            wsum += x
            newLen = 1
            while stack and stack[-1][0] <= x:
                v, ln = stack.pop()
                total -= v * ln
                newLen += ln
            stack.append((x, newLen))
            total += x * newLen
            # cost = total - wsum; shrink from left while > k
            while total - wsum > k:
                v, ln = stack[0]
                total -= v
                wsum -= rev[I]
                if ln == 1:
                    stack.pop(0)
                else:
                    stack[0] = (v, ln - 1)
                I += 1
            ans += J - I + 1
        return ans

Looking at this problem:

- Minimum cost to make subarray `[l,r]` non-decreasing using increments: `f[l]=nums[l]`, `f[i]=max(nums[i], f[i-1])`, cost = `sum(max(nums[l..i]) - nums[i])`.
- Working on the **reversed** array, this becomes: cost = `sum(max(rev[j..J]) - rev[j])` (suffix max from the right endpoint), i.e., each element must be raised to the max of everything from it to the right end of the window.
- For fixed right end `J`, cost is non-increasing as left end `I` increases (removing the leftmost element only removes a non-negative term and never changes suffix maxes of the rest). Also cost only grows as `J` grows → two pointers works.
- Maintain the window's suffix-max decomposition as a monotonic stack of `(value, length)` segments with values strictly decreasing bottom→top: adding `x=rev[J]` pops (from top) all segments with value ≤ x and merges them; shrinking removes one element from the bottom segment. `total` = sum of segment maxes; cost = `total - wsum`.

I verified both examples by hand:
- Example 1 (`rev=[4,4,2,1,3,6]`): traces to 17 ✓
- Example 2 (`rev=[6,3,1,3,6]`): traces to 12 ✓

Key edge cases: guard top-popping so it never consumes dead (already-shrunk) bottom segments (use a head pointer); equality values must also be popped/merged; when window is a single element cost is 0 so the shrink loop always terminates.

```python
class Solution:
    def countNonDecreasingSubarrays(self, nums: List[int], k: int) -> int:
        rev = nums[::-1]
        n = len(rev)
        ans = 0
        I = 0
        stack = []   # segments [value, length], values strictly decreasing bottom -> top
        head = 0     # live segments are stack[head:]
        total = 0    # sum of suffix-max values over window [I, J]
        wsum = 0     # sum of rev[I..J]
        for J in range(n):
            x = rev[J]
            wsum += x
            newLen = 1
            while head < len(stack) and stack[-1][0] <= x:
                v, ln = stack.pop()
                total -= v * ln
                newLen += ln
            stack.append((x, newLen))
            total += x * newLen
            # cost of window = total - wsum; shrink from left while it exceeds k
            while total - wsum > k:
                v, ln = stack[head]
                total -= v
                wsum -= rev[I]
                I += 1
                if ln == 1:
                    head += 1
                else:
                    stack[head] = (v, ln - 1)
            ans += J - I + 1
        return ans
```

This runs in amortized O(n) time (each index pushed once, popped once from either side) and O(n) space, which comfortably handles n = 10⁵.
