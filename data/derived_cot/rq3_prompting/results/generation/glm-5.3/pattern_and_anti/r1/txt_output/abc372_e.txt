Key insight: k ≤ 10, so we only need the top 10 largest vertex numbers in each component. This is a classic union-find problem where each component maintains a small sorted list (max-heap or sorted list) of its top 10 elements. When merging, we merge the two lists and keep the top 10.

Approach:
- Union-Find (DSU) with union by size/rank.
- Each root stores a sorted list (descending) of up to 10 largest vertices in its component.
- On union: find roots, if different, merge lists (concatenate, sort descending, truncate to 10), attach smaller tree to larger.
- On query: find root of v, if len(list) < k, print -1, else print list[k-1].

Complexity: Each union operation merges two lists of at most 10 elements each, so it's O(10 log 10) per union ≈ O(1). Total O((N + Q) α).

Implementation details:
- Use path compression and union by size.
- Store the lists in a dictionary or array indexed by root.

## Analysis

**Decisive constraints:** N, Q ≤ 2×10⁵, but k ≤ 10 — we only ever need the top 10 vertex numbers of a component.

**Approach:** Union-Find (DSU with path halving + union by size) where each root stores a descending-sorted list of the ≤10 largest vertices in its component. On union, concatenate the two lists (each ≤10), sort, truncate to 10. On query, find root and index `list[k-1]` or -1 if too short. Each merge costs O(20 log 20) ≈ O(1), so total is ~O((N+Q)·α).

**Ledger:**
- Invariant: `top[root]` = top-10 largest vertices of that component (v itself counts, matching sample where query `2 1 2` on {1,2} → 1).
- Edge cases: duplicate edges (skip if same root); k > component size → -1; empty output when no type-2 queries.
