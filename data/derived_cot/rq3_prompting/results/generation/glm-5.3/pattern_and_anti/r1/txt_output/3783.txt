```python
class Solution:
    def permute(self, n: int, k: int) -> List[int]:
        fact = [1] * (n + 1)
        for i in range(1, n + 1):
            fact[i] = fact[i-1] * i
        used = [False] * (n + 1)
        result = []
        prev_parity = -1  # parity of previous element; -1 none
        for pos in range(n):

            # we need to compute per candidate.
            for v in range(1, n + 1):
                if used[v]:
                    continue
                p = v & 1
                if prev_parity != -1 and p == prev_parity:
                    continue
                # count completions
                # count remaining odds and evens after using v
                # total odds = (n+1)//2, evens = n//2

                    k -= f
                else:

                    result.append(v)
                    prev_parity = p
                    break
            else:

        return result
```

=== ANSWER ===
Looking at this problem:

- **Key insight**: An alternating permutation's parity pattern is fully determined by the first element's parity. Given a valid alternating prefix, the remaining positions have forced parities, so the number of completions is `o_rem! * e_rem!` — provided the remaining odd/even counts match the remaining odd/even slots (a pattern can be globally infeasible, e.g., n=3 starting with even needs 2 evens but only 1 exists).
- **Algorithm**: Standard k-th permutation construction — at each position, try unused values in increasing order, check parity alternation, count completions with the factorial formula (with slot-match check, else count = 0), and either skip (subtract from k) or fix the value.

**Ledger**: invariant = prefix stays alternating; slot counts computed from remaining length R and last parity (odd slots = `(R+1)//2` if last parity even, `R//2` if odd); edge cases: n=1, infeasible parity patterns (count 0), k out of range (return []).

Traced against all three examples (n=4,k=6 → [3,4,1,2]; n=3,k=2 → [3,2,1]; n=2,k=3 → []) — all correct, including the tricky n=3 case where starting with 2 yields count 0.

```python
        for i in range(1, n + 1):
            fact[i] = fact[i - 1] * i
        total_odd = (n + 1) // 2
        total_even = n // 2
        used = [False] * (n + 1)
        result = []
        used_o = 0
        used_e = 0
        prev_parity = -1
        for pos in range(n):
            placed = False
            for v in range(1, n + 1):
                if used[v]:
                    continue
                p = v & 1
                if prev_parity != -1 and p == prev_parity:
                    continue
                no = used_o + (1 if p == 1 else 0)
                ne = used_e + (1 if p == 0 else 0)
                R = n - (pos + 1)
                # remaining slots: next position has parity 1-p, alternating
                so = (R + 1) // 2 if p == 0 else R // 2
                se = R - so
                o_rem = total_odd - no
                e_rem = total_even - ne
                if o_rem == so and e_rem == se:
                    f = fact[o_rem] * fact[e_rem]
                else:
                    f = 0
                if k > f:
                    k -= f
                else:
                    used[v] = True
                    result.append(v)
                    prev_parity = p
                    used_o, used_e = no, ne
                    placed = True
                    break
            if not placed:
                return []
        return result
```
