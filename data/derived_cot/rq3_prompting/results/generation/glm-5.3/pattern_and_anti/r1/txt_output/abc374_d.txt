We have N ≤ 6 line segments. We start at (0,0). For each segment, we must travel (laser off) at speed S to one endpoint, then print the segment at speed T (printing takes length/T). We want the minimum total time.

The order of printing segments is a permutation (at most 6! = 720), and for each segment we choose direction (2 choices), so 720 * 64 = 46080 combinations — trivial to brute force. Actually even simpler: bitmask DP over subsets: dp[mask][i][d] = min time to print segments in mask, ending at endpoint d of segment i. With N=6, mask up to 64, states 64*6*2 = 768, transitions 6*2 each — trivial.

Let me define for segment i: P[i][0] = (A_i, B_i), P[i][1] = (C_i, D_i). Length L[i] = dist(P[i][0], P[i][1]).

dp over mask: dp[mask] is a dict/array of (last segment index, ending endpoint) → min time. Start: mask empty, position (0,0), time 0.

Transition: from state (mask, i, e) where e is the ending endpoint (so current position is P[i][e]), for each j not in mask, for each direction d in {0,1}: move from current position to P[j][d] at speed S, then print segment j from P[j][d] to P[j][1-d], taking L[j]/T. New time = time + dist/S + L[j]/T, ending endpoint 1-d.

Answer: min over all states with full mask.

Edge cases: overlapping segments must be printed separately — that's automatically handled since we treat each segment independently (we just print each one; overlapping doesn't matter).

Note: the move while not emitting must be at speed S — the minimum time for a straight move is dist/S. Movement can be in any direction, so straight line is optimal.

Also, an interesting subtlety: could it ever help to not go directly? No, since Euclidean distance is the metric, direct straight-line travel at speed S is optimal (triangle inequality).

One more subtlety: could it help to print a segment while passing over it during travel? No — you must first move to an endpoint and print the whole segment; the laser is off during travel. So each segment costs exactly dist/S (to its chosen start endpoint from previous position) + L/T.

Complexity: DP with bitmask: 2^6 * 6 * 2 states, each with 12 transitions → trivially fast.

=== ANSWER ===
**Approach.** N ≤ 6, so exhaustive search over orderings and print directions is tiny (6!·2⁶). Use bitmask DP: state (mask, last segment, ending endpoint) → minimal time. Cost of printing segment j starting from endpoint d after being at position p is dist(p, endpoint d)/S + length(j)/T. Direct straight-line travel is optimal (triangle inequality), and each segment must be printed entirely from one endpoint, so this cost model is exact.

**Key details.** Start position (0,0) with empty mask; answer is min over all full-mask states. Complexity: 2⁶·6·2 states × 12 transitions — trivial.

Verified against sample 1 (order 2→1→3 yields 2 + √2/2 + √5 + 1/2 + 1) and sample 2 (print (0,2)-(2,0) first then the diagonal from (0,0): 20.9705627…). Samples 3–4 are pure enumerations the DP covers.
