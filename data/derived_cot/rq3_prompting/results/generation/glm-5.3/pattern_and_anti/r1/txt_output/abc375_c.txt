```python
import sys
import numpy as np

def main():
    data = sys.stdin.buffer.read().split()
    N = int(data[0])
    A = np.frombuffer(b''.join(data[1:1 + N]), dtype=np.uint8).reshape(N, N)
    B = A.copy()
    for d in range(N // 2):
        k = (d + 1) % 4
        if k == 0:
            continue
        lo = d
        hi = N - 1 - d
        rot = np.rot90(A[lo:hi + 1, lo:hi + 1], -k)  # k quarter-turns clockwise (view)
        B[lo, lo:hi + 1] = rot[0, :]
        B[hi, lo:hi + 1] = rot[-1, :]
        B[lo:hi + 1, lo] = rot[:, 0]
        B[lo:hi + 1, hi] = rot[:, -1]
    sys.stdout.buffer.write(b'\n'.join(B[i].tobytes() for i in range(N)) + b'\n')

main()
```

Looking at this problem:

- Operation *i* rotates the concentric sub-square `[i, N+1-i] × [i, N+1-i]` by 90° clockwise (target `(y, N+1-x)` receives source `(x,y)`), as confirmed against the intermediate grids in Sample 1.
- All operations rotate about the **same center**, so they compose additively. A cell on ring `d = min(r-1, c-1, N-r, N-c)` (0-indexed) lies inside exactly the squares for `i = 1..d+1`, so its net rotation is `(d+1) × 90°` clockwise.
- Therefore: each ring `d` of the final grid equals ring `d` of the input rotated by `(d+1) mod 4` quarter-turns clockwise. Rings are disjoint, so this can be done ring-by-ring: take the border of `rot90(sub-square, 4-k)` and write it into the output ring.

I verified this cell-by-cell against all three samples (multiple cells per ring, including the identity rings where `(d+1)%4==0`), and all matched (several apparent mismatches turned out to be my own misreadings of grid characters/rows, each resolving in the formula's favor).

Implementation uses numpy: per ring, `rot90` is just a view, and only the border (O(perimeter)) is copied — total O(N²) byte copies, tiny memory (two 9 MB grids for N=3000), well within limits. Corners get written twice with identical values, which is harmless.
