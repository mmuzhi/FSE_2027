There are N types of products, each having 10^{100} units in stock.
You can buy any non-negative number of units of each product. To buy k units of the i-th product, it costs k^2 P_i yen.
If your total purchase cost is at most M yen, what is the maximum number of units you can buy in total?

Input

The input is given from Standard Input in the following format:
N M
P_1 \ldots P_N

Output

Constraints


- 1 \leq N \leq 2 \times 10^{5}
- 1 \leq M \leq 10^{18}
- 1 \leq P_i \leq 2 \times 10^{9}
- All input values are integers.

Sample Input 1

4 1 9

Sample Output 1

3

Looking at this problem:

- Buying k units of product i costs k²P_i, so the marginal cost of the (k+1)-th unit is (2k+1)P_i. The cheapest way to buy K total units is to greedily take the K smallest marginal costs (each product's marginals form an increasing sequence).
- So I binary search on threshold T = the largest value with g(T) ≤ M, where g(T) = Σ P_i·c_i² and c_i = number of odd j with j·P_i ≤ T, i.e. c_i = (T//P_i + 1)//2. Answer = f(T) + (M − g(T)) // (T+1), since g(T+1) > M guarantees the next marginals cost exactly T+1 each and remaining budget buys fewer than the available ones.

Complexity: O(N log M). To keep Python fast I use numpy; to avoid int64 overflow for huge T I first compute an approximate g in float64 — if it exceeds 8e18 (far above M ≤ 1e18), it's infeasible; otherwise exact g ≤ ~8e18 fits in int64 (each term and the sum), so exact computation is safe.

Verified against sample 1 (T=4, count 3, cost 8, answer 3) and hand-checked sample 2 (T=38, g=975, count 53, answer 53).
