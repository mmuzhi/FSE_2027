Looking at this problem:

- For each choice of bottom mochi j, any top mochi i with `2*A[i] <= A[j]` works. Since `A[i] >= 1`, this condition implies `A[i] < A[j]`, so the pair automatically uses two distinct mochi.
- The array is sorted, so for each j the count of valid tops is `bisect_right(A, A[j] // 2)` (since `2*A[i] <= A[j]` ⟺ `A[i] <= floor(A[j]/2)` for integers).
- Sum over all j: O(N log N), fine for N = 5×10⁵.

Verification on Sample 1: counts per element = 0,0,1,1,2,4 → total 8 ✓. Sample 2: no element ≤ 194 → 0 ✓. Sample 3: hand-computed the per-element counts (fixing 278→16), total 388 ✓.
