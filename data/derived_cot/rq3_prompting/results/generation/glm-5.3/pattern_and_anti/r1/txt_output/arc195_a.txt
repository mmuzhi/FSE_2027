=== ANSWER ===
Looking at this problem:

**Key insight**: Compute the leftmost greedy match (match each B_i at the earliest possible position) and the rightmost greedy match (match each B_i at the latest possible position, scanning from the end). 

- For any match Q, the leftmost greedy result P satisfies P_i ≤ Q_i componentwise (P_1 is the first occurrence of B_1; inductively, P_{k+1} is the first occurrence of B_{k+1} after P_k, and Q_{k+1} > Q_k ≥ P_k).
- Symmetrically, the rightmost greedy result R satisfies Q_i ≤ R_i componentwise.

So if P = R, every match Q is squeezed to Q = P → exactly one subsequence → "No". If P ≠ R, there are at least two distinct matches → "Yes". If no match exists → "No".

**Verification on samples**:
- Sample 1: A=[1,2,1,2], B=[1,2]. Leftmost=[0,1], rightmost=[2,3] → differ → "Yes" ✓
- Sample 2: A=[1,2,1]. Leftmost=[0,1], rightmost=[0,1] → equal → "No" ✓
- Sample 3: A=[1,1,2], B=[2,1]. Leftmost greedy fails → "No" ✓

Complexity O(N+M). Edge cases: M=N (both greedies forced equal → "No" unless match fails), single-element B with duplicate A values (left≠right → "Yes") — both handled correctly by the general argument.
