=== ANSWER ===
Looking at this problem: replacing `WA` → `AC` can only create a *new* `WA` with the `W` immediately to the left of the replaced `W` (since the replacement produces `AC`, and `A` in second position of the pair can't start a new pair to its right). So the cascade propagates leftward through a run of W's.

**Key insight:** A maximal run of `k` W's immediately followed by an `A` transforms entirely into `'A' + 'C'*k` (the W's get consumed one by one from right to left, each becoming `A` then `C` as the trigger A moves left, until the run's first W becomes the final `A` and the original A position becomes `C`). Runs are independent: the run is maximal so the character before it isn't `W`, and replacements never produce new `W`'s, so no cross-run interaction occurs.

**Verification with samples:**
- `WACWA`: run(W@0, A@1)→`AC`, `C`, run(W@3, A@4)→`AC` ⇒ `ACCAC` ✓
- `WWA`: `k=2` → `ACC` ✓  
- `WWWWW`: no run followed by A → unchanged ✓
- Extra check `WWAWWA` → `ACC` + `ACC` = `ACCACC`; direct simulation: `WWAWWA → WACWWA → ACCWWA → ACCWAC → ACCACC` ✓

**Algorithm (O(n)):** scan left to right, keep a counter of pending W's. On `A` with pending W's, emit `'A' + 'C'*count` and reset; on `A` with none, emit `A`; on any other char (or end of string), flush pending W's as-is then emit the char.

Edge cases handled: trailing W's at end of string stay `W`; W's followed by a non-`A` letter stay `W`.

                out.append('W' * w)
                w = 0
            out.append(ch)
    if w:
        out.append('W' * w)
    sys.stdout.write(''.join(out) + '\n')

main()
