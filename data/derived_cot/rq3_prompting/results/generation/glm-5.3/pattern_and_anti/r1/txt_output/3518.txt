Great, the DP works. Edge cases:
1. Negative infinity handling — must initialize non-zero states to -inf so they don't propagate invalid combos. In Python use float('-inf').
2. Update order: must update from dp[4] down to dp[1] (using previous dp values for lower states), so a single b[i] isn't used for multiple a elements.

Since dp values are integers except -inf, adding a[3]*b[i] to -inf keeps -inf (float), which is fine for max comparisons.

One tiny concern: with float('-inf'), the final result dp[4] is guaranteed to be an integer (finite) because b.length >= 4 ensures a valid selection exists. So returning dp[4] is fine. Actually when we compute max(-inf, finite), the result is the finite int. Good.

Implementation:

```python
class Solution:
    def maxScore(self, a: List[int], b: List[int]) -> int:
        NEG = float('-inf')
        dp = [NEG, NEG, NEG, NEG, NEG]
        dp[0] = 0
        for x in b:
            for k in (4, 3, 2, 1):
                cand = dp[k-1] + a[k-1] * x
                if cand > dp[k]:
                    dp[k] = cand
        return dp[4]
```

Wait, one subtlety: dp[k-1] + a[k-1]*x — if dp[k-1] is -inf (float), adding an int gives -inf float, fine. If dp[k-1] is finite int, result is int. dp[k] comparison between int and -inf float works fine.

This is O(n) time, O(1) space.
