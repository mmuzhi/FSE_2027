=== ANSWER ===
Looking at this problem:

- **Key constraint**: N, Q up to 2×10⁵, so we need O(1)-ish per query.
- **Approach**: Maintain a running count of "ABC" occurrences. When position p (0-indexed) changes, only occurrences starting at p-2, p-1, p can be affected. Subtract matches before the change, apply the change, add matches after.
- **Invariant**: `cnt` always equals the number of "ABC" substrings in current S; each query locally updates only the ≤3 windows containing position p.
- **Edge cases**: boundary starts (0 ≤ start ≤ n-3), and queries where the character doesn't change (subtract-then-add handles it naturally).

Verified logic against all three samples by hand-tracing (e.g., sample 1: initial cnt=2, each query correctly yields 2,1,1,0; sample 3 traced fully matches 0,0,0,0,1,1,2,2,1,1).

import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    q = int(data[1])
    s = list(data[2].decode())
    idx = 3

    cnt = 0
    for i in range(n - 2):
        if s[i] == 'A' and s[i+1] == 'B' and s[i+2] == 'C':
            cnt += 1

    out = []
    m = n - 3
    for _ in range(q):
        p = int(data[idx]) - 1

        for st in (p-2, p-1, p):
            if 0 <= st <= m and s[st] == 'A' and s[st+1] == 'B' and s[st+2] == 'C':
                cnt -= 1

        s[p] = c

        for st in (p-2, p-1, p):
            if 0 <= st <= m and s[st] == 'A' and s[st+1] == 'B' and s[st+2] == 'C':
