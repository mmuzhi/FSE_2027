- The removal sequence is fixed: 10, 9, 8, ..., 1 (each player removes 1 fewer than the previous opponent).
- Alice makes moves 1, 3, 5, ... (odd-indexed moves in the sequence), Bob makes even-indexed moves.
- A move is possible only if the remaining stones ≥ the required removal amount.
- Alice wins iff the total number of successfully completed moves is odd (meaning Bob is the one who faces an impossible move).

Key check: cumulative sums are 10, 19, 27, 34, 40, 45, 49, 52, ... Since n ≤ 50 < 52, at most 7 moves occur, so a simple simulation handles everything.

- n = 12: Alice removes 10 (k=1 moves done since 19 > 12), Bob can't remove 9 → k=1 odd → Alice wins. ✓
- n = 1: no move possible, k=0 even → Alice loses. ✓

- State: `stones` remaining, `take` = current required removal, `moves` = count of completed moves.
- Invariant: each loop iteration executes exactly one legal move, decrementing `take`.
- Edge cases: n < 10 (loop never runs, return False); guard `take >= 1` for safety.
