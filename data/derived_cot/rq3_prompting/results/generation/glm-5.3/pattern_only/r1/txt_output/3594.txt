        total = sum(nums)

=== ANSWER ===
**Commit.** Key invariant: if index `i` is the outlier and index `j` is the sum element, then `total - nums[i] - nums[j] = nums[j]`, so `nums[j] = (total - nums[i]) / 2`. Thus value `x` is a potential outlier iff `total - x` is even and the value `s = (total - x) / 2` exists at some *different* index — i.e., `s in counter` when `s != x`, or `count[x] >= 2` when `s == x`. This is O(n).

**Implementation ledger:** counter over values (validity is purely value-based); parity check via Python `% 2` (safe for negatives); take max over valid candidates.

**Recheck on examples:** Ex1: total=20, x=10 → s=5 present → 10 ✓. Ex2: total=-8, x=4 → t=-12, s=-6 present ✓ (max). Ex3: total=15, x=5 → t=10, s=5==x, count 2≥2 → 5 ✓. Edge: outlier equal to sum element needs the count≥2 branch (Ex3 covers it); odd `total - x` skipped correctly even when negative.
