=== ANSWER ===
**Approach.** A query asks whether the multisets of `A[l..r]` and `B[L..R]` are equal. Assign each value `v ∈ [1,N]` an independent uniform random hash `h[v] ∈ Z_p` with `p = 2^61 − 1`. Build prefix sums `PA`, `PB` of the hashes along `A` and `B`. The multisets are equal iff `PA[r] − PA[l−1] ≡ PB[R] − PB[L−1] (mod p)` (plus the trivially necessary equal length `r−l == R−L`). If multisets differ, the difference is a nonzero linear form `Σ c_v·h[v]` in independent uniform values, so it vanishes with probability `1/p ≈ 4·10^-19` per query — negligible over `Q ≤ 2·10^5` queries. Since hashes are random at runtime, no fixed test can target them.

**Ledger.**
- Invariant: prefix hashes are running sums mod `p`; per query one modular comparison of range differences.
- Edge cases: unequal lengths (explicit length check); negative differences handled by `% p`.

Verified against both samples (e.g., sample 1 query 3: multisets `{1,2,2,3}` vs `{1,2,3,4}` differ → No; sample 2 query 3: lengths 3 vs 4 → No).
