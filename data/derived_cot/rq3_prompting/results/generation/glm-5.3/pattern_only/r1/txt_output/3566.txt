```python
class Solution:
    def stringSequence(self, target: str) -> List[str]:
        res = []
        cur = []
        for c in target:
            cur.append('a')
            res.append(''.join(cur))
            ch = 'a'
            while ch != c:
                ch = chr(ord(ch) + 1)
                cur[-1] = ch
                res.append(''.join(cur))
        return res
```

```python
class Solution:
    def stringSequence(self, target: str) -> List[str]:
        res = []
```

```python
class Solution:
    def stringSequence(self, target: str) -> List[str]:
        res = []
```

**Commit (analysis):** The process is fully forced: each character of `target` requires exactly one key-1 press (appending 'a') followed by exactly `ord(c) - ord('a')` key-2 presses to walk the last character from 'a' up to `c` (key 2 only increments forward, and wrapping around would cost more). So the minimal press sequence is unique and every screen state must be recorded. For each position `i`, the strings shown are `target[:i] + ch` for `ch` from `'a'` through `target[i]`.

**Ledger:** invariant — prefix before position `i` is exactly `target[:i]`; transition — enumerate `chr(97..ord(c))` appended to that prefix; edge case — character `'a'` yields a single state (zero key-2 presses), verified in Example 1.

**Recheck (Example 2, "he"):** i=0: "a".."h"; i=1, prefix "h": "ha".."he" — matches. Worst-case size: 400 × 26 strings × ≤400 chars ≈ 4.2M characters — fine.

```python
class Solution:
    def stringSequence(self, target: str) -> List[str]:
        res = []
        base = ord('a')
        for i, c in enumerate(target):
            prefix = target[:i]
            for k in range(ord(c) - base + 1):

        return res
```
