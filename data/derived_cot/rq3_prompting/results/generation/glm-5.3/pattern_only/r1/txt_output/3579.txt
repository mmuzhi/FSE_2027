We have an array of 3 integers, each between 1 and 127. We need to concatenate their binary representations in some order to maximize the resulting number. Return that maximum number.

Since there are only 3 elements, there are at most 6 permutations. The simplest and most robust approach: try all permutations, compute the concatenated value, and take the max.

How to compute the concatenated value: for a permutation (a, b, c), the value is ((a << bitlen(b)) | b) shifted again... Specifically:

result = a
result = (result << bit_length(b)) | b
result = (result << bit_length(c)) | c

where bit_length is the number of bits in the binary representation. Since nums[i] >= 1, bit_length >= 1, no issue with zero.

Alternative: comparator-based sorting. Compare two numbers a, b: a should come before b if bin(a)+bin(b) > bin(b)+bin(a) as binary strings. But with only 3 elements, permutations are simpler and less error-prone.

- All equal numbers, e.g., [5,5,5] → 5*2^3 + 5*2^3 + 5 = "101101101" = 365. Permutations all give same result, fine.
- Single-bit numbers like [1,1,1] → "111" = 7.

class Solution:
    def maxGoodNumber(self, nums: List[int]) -> int:
        best = 0
        for perm in permutations(nums):

**Commit:** With only 3 elements, exhaustively evaluate all 6 permutations — compute each concatenation via shift-and-or using `bit_length()`, and take the maximum. Invariant: `val = (val << x.bit_length()) | x` correctly appends `x`'s binary digits (no leading-zero ambiguity since `nums[i] >= 1`).
