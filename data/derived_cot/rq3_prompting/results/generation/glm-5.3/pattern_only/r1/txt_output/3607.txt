```python
    def minOperations(self, nums: List[int]) -> int:
        M = max(nums) if nums else 1
        # sieve of smallest prime factor
        spf = list(range(M + 1))
        i = 2

            if spf[i] == i:  # i is prime
                for j in range(i * i, M + 1, i):
                    if spf[j] == j:
                        spf[j] = i
            i += 1
        n = len(nums)

            if x <= cap:
                cap = x
            else:
                s = spf[x]
                if s > cap:
                    return -1
                ops += 1
                cap = s
        return ops
```

```python
from typing import List

class Solution:
    def minOperations(self, nums: List[int]) -> int:
```

```python
from math import isqrt
from typing import List


class Solution:
    def minOperations(self, nums: List[int]) -> int:
        # One operation sends x -> x / gpd(x). Since gpd(x) = x / spf(x),
        # the element becomes spf(x). Primes and 1 are fixed points, so each
        # element has at most two reachable values: x (0 ops) and spf(x) (1 op).
        M = max(nums)
        limit = isqrt(M)  # spf of any composite <= M never exceeds limit

        # Primality of 2..limit (limit <= 1000)
        comp = bytearray(limit + 1)
```

Looking at this problem:

**Key insight:** The greatest proper divisor of `x` is `x / spf(x)` where `spf` is the smallest prime factor. So one operation maps `x → x / (x/spf(x)) = spf(x)`. Since `spf(x)` is prime, and dividing a prime by its greatest proper divisor (which is 1) leaves it unchanged, each element has at most **two reachable values**: `x` (0 ops) or `spf(x)` (1 op). Primes and 1 are immovable (this explains example 2's `-1`).

**Greedy:** Process right-to-left, keeping each element as large as allowed (a larger value never hurts elements to its left). The last element stays unchanged. For each element: if `x ≤ cap`, keep it; otherwise it must become `spf(x)` — if that still exceeds `cap`, return `-1`. An exchange argument (greedy caps dominate any feasible solution's caps) proves optimality.

**Implementation:** SPF sieve up to `max(nums) ≤ 10^6`. For composite `j`, `spf(j)² ≤ j`, so `spf(j) ≤ isqrt(M)`; writing prime slices in *descending* order makes the smallest prime factor the final writer (fast C-level slice assignments).

Verified against all three examples and edge cases (primes, value 1, single element, `[7,7,6] → -1`, `[25,7] → 1`, `[4,4,2] → 2`).
