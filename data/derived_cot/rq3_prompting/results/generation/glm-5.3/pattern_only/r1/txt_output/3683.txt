```python
class Solution:
    def answerString(self, word: str, numFriends: int) -> str:
        n = len(word)
        if numFriends == 1:
            return word
        m = n - numFriends + 1
        best = ""
        for i in range(n):
            cand = word[i:i+m]
            if cand > best:
                best = cand
        return best
```

=== ANSWER ===
Looking at this problem:

- A piece `word[i:j]` appears in some split iff the rest can form `numFriends-1` non-empty parts, which reduces to the length constraint `j - i <= n - numFriends + 1` (for `numFriends >= 2`, every starting position admits its maximal-length candidate: prefixes, suffixes, and interior substrings can all be completed into a valid split).
- For any start `i`, longer is lexicographically ≥ shorter (prefix relation), so the best candidate starting at `i` is `word[i : min(i+m, n)]` where `m = n - numFriends + 1`.
- Special case `numFriends == 1`: only the whole word is achievable (a general "max substring of length ≤ n" would wrongly pick e.g. `"b"` for `"ab"`), so return `word` directly.

Verification with examples:
- `"dbca"`, 2 → m=3, candidates `"dbc","bca","ca","a"` → `"dbc"` ✓
- `"gggg"`, 4 → m=1 → `"g"` ✓
- Extra checks: `"ab"`, 1 → `"ab"` (special case, not `"b"`); `"cacb"`, 2 → candidates `"cac","acb","cb","b"` → `"cb"` (matches brute force over splits `"c|acb","ca|cb","cac|b"`).

Complexity: O(n·m) ≤ 25M character operations for n ≤ 5000, all done in C-level string slicing/comparison — easily fast enough.

```python
class Solution:
    def answerString(self, word: str, numFriends: int) -> str:
        if numFriends == 1:
            return word
        n = len(word)
        m = n - numFriends + 1  # max possible length of any piece
        return max(word[i:i + m] for i in range(n))
```
