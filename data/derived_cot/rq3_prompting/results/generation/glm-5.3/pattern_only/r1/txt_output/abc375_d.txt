=== ANSWER ===
Looking at this problem:

**Key insight:** A length-3 string is a palindrome iff its first and third characters are equal (the middle character is unconstrained, since it's always equal to itself). So I need to count triples i < j < k with S_i == S_k, and for each such pair (i, k), the number of valid j is (k − i − 1).

**Approach:** Answer = Σ over all pairs (a, b), a < b, S[a] == S[b] of (b − a − 1). Single pass: when processing position i with character c, if `cnt` earlier positions of character c exist with position-sum `sumpos`, the contribution of pairing i with all of them is `cnt·i − sumpos − cnt`.

**Verification on samples:**
- Sample 1 "ABCACC": A pair (0,3) contributes 3−0−1=2; C pairs (2,4)→1, (2,5)→2, (4,5)→0. Total 5. ✓
- Sample 2: 8 identical chars → C(8,3) = 56. ✓
- Sample 3: X at [0,3,6,8,9,10]: Σ pairs diff = Σ p_t(2t−m+1) = 70, minus C(6,2)=15 → 55. Y at [1,2,4,5,7]: 30 − 10 = 20. Total 75. ✓

**Edge cases:** length < 3 gives 0 (pair with adjacent indices contributes 0, handled naturally); Python big ints avoid overflow (max ~C(2·10⁵, 3) ≈ 1.3·10¹⁵).

Complexity: O(n) time, O(1) extra memory (26 counters/sums). Iterating over `bytes` yields ints, making the inner loop fast.
