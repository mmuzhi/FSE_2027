We need to choose a subset S of size K minimizing (max_{i∈S} A_i) × (sum_{i∈S} B_i).

Standard approach: sort items by A_i in decreasing order (or increasing). For each candidate max value A_j (i.e., the maximum A in S is exactly A_j), we must pick j (the item achieving the max) plus K-1 items from those with A_i ≤ A_j (among indices with A smaller, or equal with tie-breaking). To minimize, we pick the K-1 smallest B values among items with A ≤ A_j (excluding j itself, but including items with equal A handled carefully).

Better: sort items by A ascending. Process in order; maintain a max-heap (or use a min-heap of negated values) of B values of size K-1 (or use a max-heap keeping the K-1 smallest B's seen so far). For each position j (0-indexed after sorting by A), the candidate answer is A_j × (B_j + sum of K-1 smallest B among first j items). Then take the minimum over all j ≥ K-1.

Wait, careful with ties: if multiple items have the same A, the "max" is that same A value, and choosing among items with the same A is fine — processing sorted ascending, when we're at position j, the first j items all have A ≤ A_j, so it's valid. Any subset S with max A = A_j consists of j plus items with A ≤ A_j which appear among the first j positions (in sorted order, with ties, all items with A equal to A_j could be before or after j in sort order, but any valid selection can be realized: if S has max A value v, take the item in S achieving... actually the item at position j in our sorted order where j is the last position of S in sorted order. Then all other items of S are at positions < j, and A at position j equals v = max. So iterating over j and picking K-1 smallest B among positions 0..j-1 covers all possibilities.)

So algorithm per test case:
- Create pairs (A_i, B_i), sort by A ascending.
- Maintain a max-heap of the K-1 smallest B values among processed items. Keep running sum.
- For j from 0 to N-1: before processing item j (i.e., when computing candidate at j), the heap contains items 0..j-1. Candidate = A_j * (B_j + heap_sum) if heap has K-1 elements (i.e., j ≥ K-1). Then push B_j: if heap size < K-1, push and add to sum; else if B_j < heap top (max of the K-1 smallest), pop top, subtract, push B_j, add; else skip.

Special case K = 1: candidate = A_j * B_j for each j. The heap with K-1 = 0 elements: candidate = A_j * B_j with sum 0. Works: heap size 0 = K-1 = 0 always. Good.

Complexity: O(N log K) per test case, total O(sum N log N). With sum N ≤ 2×10^5, fine. But T up to 2×10^5, so need fast I/O in Python.

import sys
from heapq import heappush, heappop

def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    T = int(data[idx]); idx += 1
    out = []
    for _ in range(T):
        N = int(data[idx]); K = int(data[idx+1]); idx += 2
        A = data[idx:idx+N]; idx += N
        B = data[idx:idx+N]; idx += N
        pairs = sorted(zip(map(int, A), map(int, B)))
        # heap: max-heap of K-1 smallest B's (store negatives)
        heap = []
        s = 0  # sum of heap contents
        best = float('inf')
        km1 = K - 1
        for a, b in pairs:
            if len(heap) == km1:
                cand = a * (b + s)
                if cand < best:
                    best = cand
            # push b into heap
            if len(heap) < km1:
                heappush(heap, -b)
                s += b
            else:
                # heap full (size km1)
                if km1 > 0 and -heap[0] > b:
                    top = -heappop(heap)
                    s -= top
                    heappush(heap, -b)
                    s += b
        out.append(str(best))
    sys.stdout.write('\n'.join(out) + '\n')

main()

Approach: sort items by A ascending. If position j (sorted) holds the max-A element of S, the other K−1 elements come from positions < j, optimally the K−1 smallest B's among them.
