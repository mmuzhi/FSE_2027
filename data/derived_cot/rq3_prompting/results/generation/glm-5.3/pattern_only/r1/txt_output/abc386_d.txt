- 1\leq X_i,Y_i\leq N
- (X_i,Y_i)\neq (X_j,Y_j)\ (i\neq j)

=== ANSWER ===
Looking at this problem:

**Key insight:** A grid where every row is `B...BW...W` and every column is `B...BW...W` (from top) is exactly a staircase/Ferrers shape anchored at the top-left corner. If `R[r]` is the number of black cells in row `r`, the column condition is equivalent to `R[1] ≥ R[2] ≥ ... ≥ R[N]` (non-increasing).

**Constraints from fixed cells** only affect their own row:
- `B` at `(r,c)` → `R[r] ≥ c` → lower bound `lo[r] = max(c over B cells)`.
- `W` at `(r,c)` → `R[r] ≤ c-1` → upper bound `hi[r] = min(c-1 over W cells)`.

**Feasibility:** exists a non-increasing sequence with `lo[r] ≤ R[r] ≤ hi[r]`. Standard greedy: process rows in increasing order keeping `cur` = maximum allowed value so far (`cur = min(cur, hi[r])`), fail if `cur < lo[r]`. Since `N` up to `10^9` but `M ≤ 2×10^5`, only constrained rows matter (unconstrained rows have bounds `[0, N]`, which never break monotonicity since we can hold `cur` constant through them).

Verified against all four samples:
- Sample 1 → Yes ✓, Sample 2 → No ✓ (row 1 forces `R[1] ≤ 1`, then row 2 needs `R[2] ≥ 2`, violating monotonicity), Sample 3 → Yes ✓, Sample 4 → No ✓ (row 1700 W at col 1083 and row 1789 W at col 211 drive `cur` down to 210, but row 1814 has B at col 712).

Also, a row containing both `B` at column ≥ some `W`'s column gives `hi < lo`, caught by the same greedy check. Column constraints impose nothing extra — they follow from the staircase shape.

Complexity: `O(M log M)`.
