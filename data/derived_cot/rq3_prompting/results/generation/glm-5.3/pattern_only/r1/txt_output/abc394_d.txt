=== ANSWER ===
**Commit:** This is the classic multi-type bracket matching problem. The deletion of adjacent matched pairs (), [], <> reduces a string to empty **iff** the standard stack algorithm accepts it — pushing openers and requiring each closer to match the stack top.

**Why the stack invariant holds:** If a closer `c` arrives while the top is a different opener `o`, then deleting `c` requires its match directly before it; that position is blocked by `o`, and deleting `o` requires its own closer adjacent, which is blocked by `c` sitting between them — a circular dependency, so no reduction to empty exists. Conversely, if the stack algorithm succeeds, innermost pairs can be deleted bottom-up to reach the empty string.

**Ledger:**
- Invariant: stack contains only unmatched openers; closer must equal `match[c]` on top.
- Edge cases: closer with empty stack → No; leftover stack at end → No; odd-length strings fail naturally.

**Check on samples:**
- `([])<>()` → stack empties fully → Yes ✓
- `([<)]>` → `)` sees top `<` → No ✓
- `())` → `)` with empty stack → No ✓

Complexity: O(n) time and space, well within limits for n ≤ 2×10⁵.
