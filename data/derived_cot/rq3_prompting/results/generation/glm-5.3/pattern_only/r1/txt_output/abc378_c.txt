- Let B_i be the most recent position before i where an element equal to A_i appeared. If such a position does not exist, let B_i = -1.

**Problem summary:**
- Given a sequence A of N positive numbers (N up to 2×10^5, A_i up to 10^9).
- For each i, B_i = the largest j < i such that A_j = A_i, or -1 if no such j exists.

**Decisive constraints:**
- N up to 2×10^5, so O(N log N) or O(N) is needed; O(N²) would be 4×10^10 operations — too slow.
- A_i values up to 10^9, so we can't use a direct array indexed by value; we need a hash map (dictionary in Python) to store the last seen position of each value.

**Approach:**
The only truly plausible approach is a single left-to-right scan with a dictionary mapping each value to its most recent position:

1. Initialize an empty dictionary `last = {}`.
2. For i from 1 to N (1-indexed):
   - If A_i is in `last`, set B_i = `last[A_i]`; otherwise B_i = -1.
   - Update `last[A_i] = i`.
3. Output B separated by spaces.

This is O(N) average time (hash map operations are O(1) average), and O(N) space for the dictionary and result list.

Alternative approach: coordinate-compress values and use an array instead of a dict. This avoids potential hash-collision worst cases but in Python, dict is fine for competitive programming. The dict approach is simpler and standard.

**Implementation ledger:**
- Main invariant: after processing index i, `last[v]` holds the most recent position where value v appeared among positions 1..i.
- Key transition: lookup `last.get(A_i, -1)` gives B_i (but careful: positions are 1-indexed; if we use 0-indexed positions internally, we need +1 when outputting, or just iterate with 1-indexed positions).
- Edge cases:
  - N = 1: output just "-1".
  - All same values: e.g., N=3, A = [5,5,5] → B = [-1, 1, 2].
  - Large values (up to 10^9): handled by dict.

**Ledger:**
- Invariant: after processing index i (1-based), `last[v]` = most recent position of value v among A_1..A_i. So when processing A_i, `last.get(x, -1)` is exactly the largest j < i with A_j = A_i, or -1.
- Edge cases: N=1 (just -1), all-equal values (chain -1, 1, 2, ...), 1-based output positions — handled by `enumerate(..., 1)`.
- Fast I/O via `sys.stdin.buffer.read()` and a single joined output.

**Recheck on samples:** Sample 1 [1,2,1,1,3] → -1 -1 1 3 -1 ✓. Sample 2 [1,10⁹,10⁹,1] → -1 -1 2 1 ✓. Invariant confirms correctness for the all-same and N=1 cases.
