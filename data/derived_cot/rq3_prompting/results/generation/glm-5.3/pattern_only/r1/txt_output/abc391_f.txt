Looking at this problem:

- Value $V(i,j,k)=A_iB_j+B_jC_k+C_kA_i$ is monotone in each variable separately (all positive), so after sorting A, B, C descending, $V$ is non-increasing in each index — a monotone 3D grid.
- With $K \le 5\times10^5$, a max-heap enumeration works: start at $(0,0,0)$; on popping $(i,j,k)$ push $(i{+}1,j,k)$ always, $(0,j{+}1,k)$ only if $i=0$, $(0,0,k{+}1)$ only if $i=0,j=0$. Each cell then has a unique predecessor, is pushed exactly once, and the invariant "every unpopped cell has a chain-successor cell in the heap that is coordinate-wise ≤ it" guarantees pops occur in non-increasing value order. So the $K$-th pop is the answer — total $O(K\log K)$ heap operations.

**Implementation ledger:** encode entries as single ints `((BIG - v) << 54) | (i<<36) | (j<<18) | k` ($v \le 3\cdot10^{18} < 2^{62}$, indices $<2^{18}$) so heapq compares plain ints; decode via shifts. Edge cases: $K=1$ (skip loop), bounds checks on each push. Verified on sample 1: pops give 44,38,36,34 then final 31 ✓; ties (sample 2) fine since any tie order keeps values non-increasing.
