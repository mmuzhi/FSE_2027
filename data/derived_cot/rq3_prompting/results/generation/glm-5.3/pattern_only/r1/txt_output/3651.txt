Implementation:

```python
class Solution:
    def constructTransformedArray(self, nums: List[int]) -> List[int]:
        n = len(nums)
        return [nums[(i + nums[i]) % n] for i in range(n)]
```

=== ANSWER ===
**Commit:** The three cases collapse into one formula. Moving `k` steps right from `i` lands at `(i+k) % n`; moving `k` steps left lands at `(i-k) % n`. Since for negative `nums[i]` we move `nums[i]` steps net (negative = left), every case is `result[i] = nums[(i + nums[i]) % n]` — and Python's `%` already yields a non-negative index for positive `n`. The `nums[i] == 0` case degenerates to `nums[i]` itself, matching the rule.

**Ledger:**
- Invariant: `(i + nums[i]) % n` is always in `[0, n)` in Python.
- Edge cases: n=1 (any shift wraps to index 0 → result[0]=nums[0], correct); zero values (land on self).

**Check against examples:**
- `[3,-2,1,1]`: `(0+3)%4=3→1`, `(1-2)%4=3→1`, `(2+1)%4=3→1`, `(3+1)%4=0→3` → `[1,1,1,3]` ✓
- `[-1,4,-1]`: `(0-1)%3=2→-1`, `(1+4)%3=2→-1`, `(2-1)%3=1→4` → `[-1,-1,4]` ✓

Both match; O(n) time, well within constraints.

```python
class Solution:
    def constructTransformedArray(self, nums: List[int]) -> List[int]:
        n = len(nums)
        return [nums[(i + nums[i]) % n] for i in range(n)]
```
