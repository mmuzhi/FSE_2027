=== ANSWER ===
Looking at this problem, the key insight is a decomposition: any jump path visits stops i₀=0 < i₁ < ... < iₖ=n-1, and the total score equals the sum over each unit step t (from t to t+1) of nums[s(t)], where s(t) is the largest chosen stop ≤ t. 

- **Upper bound**: v_t = nums[s(t)] ≤ max(nums[0..t]) for every t, so total ≤ Σₜ max(nums[0..t]).
- **Achievability**: Stop at every strict prefix-maximum position (and at n-1). Then s(t) is exactly the prefix-maximum position for each t, achieving the bound.

Verification with examples:
- [1,3,1,5]: prefix maxes over steps t=0..2 are 1,3,3 → 7 ✓
- [4,3,1,3,2]: steps t=0..3 all have max 4 → 16 ✓

Implementation ledger: maintain running max `cur`, add it for each of the n-1 unit steps. Edge case n=1: loop is empty, return 0 (no jumps needed). Complexity O(n) time, O(1) space — well within limits.

Recheck on draft: at t=0, cur = max(nums[0], nums[0]) = nums[0] ✓; cur updates to include nums[t] before adding, so at step t it holds max(nums[0..t]) ✓. Max sum ≈ 10⁵·10⁵ = 10¹⁰, fine for Python ints.

```python
class Solution:
    def findMaximumScore(self, nums: List[int]) -> int:
        total = 0
        cur = nums[0]
        for t in range(len(nums) - 1):
            if nums[t] > cur:
                cur = nums[t]
            total += cur
        return total
```
