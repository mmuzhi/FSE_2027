=== ANSWER ===
Looking at this problem:

- For each query, I need the smallest day `d >= d_j` with `d ≡ r_t (mod q_t)`.
- Key formula: let `rem = d_j mod q`. If `rem <= r`, answer is `d_j + (r - rem)`; otherwise we wrap around to the next cycle: `d_j + (q - rem) + r`.
- Constraints are tiny (N, Q ≤ 100), so a direct per-query O(1) computation is more than enough — no precomputation or data structures needed.

Verification with sample (q=7, r=3): d=1 → rem=1≤3 → 1+2=3 ✓; d=3 → rem=3 → 3 ✓; d=4 → rem=4>3 → 4+3+3=10 ✓; d=15 → rem=1 → 17 ✓. Type 2 (q=4, r=2), d=7 → rem=3>2 → 7+1+2=10 ✓.

Edge cases: `rem == r` (collected same day) handled by `rem <= r`; `r = 0` works since `rem = 0 ≤ 0`. Python big ints handle values up to ~2×10⁹ trivially.
