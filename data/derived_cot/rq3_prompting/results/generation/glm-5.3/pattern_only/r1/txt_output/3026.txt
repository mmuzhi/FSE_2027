```python
class Solution:
    def minimumPossibleSum(self, n: int, target: int) -> int:
        MOD = 10**9 + 7
        m = min(n, target // 2)
        r = n - m
        total = m * (m + 1) // 2 + r * target + r * (r - 1) // 2
        return total % MOD
```

=== ANSWER ===
Looking at this problem:

- The conflict structure is a perfect matching on numbers below `target`: each `x` in `1..⌊(target-1)/2⌋` conflicts only with `target - x`; `target/2` (even target) is safe due to distinctness; numbers `≥ target` conflict with nothing.
- Greedy: take `m = min(n, target // 2)` smallest numbers `1..m` (always prefer the smaller endpoint of each conflicting pair, and `target/2` is free). Then the remaining `r = n - m` smallest safe numbers are `target, target+1, ..., target+r-1`.
- Sum = `m(m+1)/2 + r·target + r(r-1)/2`, mod 1e9+7.

Verification on examples:
- n=2, target=3: m=1, r=1 → 1 + 3 = 4 ✓
- n=3, target=3: m=1, r=2 → 1 + 6 + 1 = 8 ✓
- n=1, target=1: m=0, r=1 → 0 + 1 + 0 = 1 ✓

Edge check (target even, e.g. target=6): m=3 takes {1,2,3} — no two distinct elements sum to 6 (only 3+3 would, needs duplicate); forbidden partners are 5, 4; next safe are 6,7,... correct.
