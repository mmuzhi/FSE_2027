```python
class Solution:
    def minDamage(self, power: int, damage: List[int], health: List[int]) -> int:
        from fractions import Fraction
        enemies = [((h + power - 1) // power, d) for h, d in zip(health, damage)]
        enemies.sort(key=lambda x: Fraction(-x[1], x[0]))  # d/t descending
        total = 0
        time = 0
        for t, d in enemies:
            time += t
            total += d * time
        return total
```

=== ANSWER ===
Looking at this problem:

- Enemy i needs `t_i = ceil(health[i] / power)` seconds of attacks to die.
- Enemies deal damage *before* Bob attacks each second, so an enemy killed at second `C_i` contributes `damage[i] * C_i` total damage, where `C_i` is the cumulative sum of `t_j` over enemies killed up to and including i.
- This is the classic weighted completion time scheduling problem: minimize `Σ d_i * C_i`. By the exchange argument (swapping adjacent i, j changes cost by `d_j*t_i − d_i*t_j`), the optimal order sorts enemies by decreasing ratio `d_i / t_i`.

Verification with Example 1: t = [1,2,2,2], ratios [1,1,1.5,2] → order 3,2,0,1 with C = 2,4,5,7 → 4·2+3·4+1·5+2·7 = 39 ✓. Example 2: order 0,1,2,3 → 1+3+6+10 = 20 ✓. Example 3: t=8 → 40·8=320 ✓.

Implementation ledger:
- Invariant: process in sorted order, accumulate time, add `d * time`.
- Edge case: exact ratio comparison — use `Fraction` (d, t ≤ 10⁴ so ties/order are exact).
- Overflow: Python ints handle up to ~10¹⁸ naturally.

```python
from fractions import Fraction
from typing import List

class Solution:
    def minDamage(self, power: int, damage: List[int], health: List[int]) -> int:
        enemies = [((h + power - 1) // power, d) for h, d in zip(health, damage)]
        # sort by damage-per-second-per-hit-time ratio d/t descending (exact via Fraction)
        enemies.sort(key=lambda x: Fraction(x[1], x[0]), reverse=True)
        total = 0
        time = 0
        for t, d in enemies:
            time += t
            total += d * time
        return total
```
