=== ANSWER ===
Looking at this problem:

- **Constraints**: N ≤ 100, A_i ≤ 100, so total sum ≤ 10000. Each operation reduces the sum by 2, giving at most 5000 operations. Direct simulation with sorting each step costs ~5000 × O(N log N) ≈ trivial.

- **Approach commitment**: Direct simulation is clearly sufficient — no need for a mathematical formula (though `min(s//2, s - max)` also works, simulation is safer and provably correct by definition of the process).

- **Invariant**: Before each operation there are ≥ 2 positive elements, so after sorting descending, both A[0] and A[1] are ≥ 1; decrementing keeps all values non-negative. Loop stops when positive count ≤ 1.

**Verification against samples**:
- Sample 1: (1,2,3,3) → 4 operations, traced step by step matches.
- Sample 2: (1,1,100): sorted (100,1,1)→(99,0,1), then (99,1,0)→(98,0,0), answer 2. ✓

Edge cases: N=2 with (1,1) → 1 operation, then stops. No negatives can appear since the two decremented values are the largest and both positive when the loop runs.

n = int(input())
a = list(map(int, input().split()))
count = 0
while sum(1 for x in a if x > 0) > 1:
