```python
class Solution:
    def minOperations(self, nums: List[int], k: int) -> int:
```

=== ANSWER ===
Looking at this problem:

**Key invariant analysis:** For `h` to be valid (and useful), all values strictly greater than `h` must be identical — meaning `h` must sit between the second-largest distinct value `v_{m-1}` and the max `v_m` (i.e., `v_{m-1} ≤ h < v_m`). Such an operation only transforms the current maximum class into `h`. Therefore each operation reduces the count of *distinct values* by at most 1 — and specifically the count of distinct values strictly greater than `k` by at most 1 (since values ≤ `h` are untouched, and `h` can't be pushed below `k` while other values ≥ `k` exist, as that would break validity).

**Impossibility:** Values never increase. If any element is `< k`, return -1.

**Lower bound & achievability:** We must eliminate every distinct value `> k`, one operation each (at most one eliminated per operation). This bound is achievable: process distinct values above `k` in descending order, each time using `h` equal to the next-lower distinct value, finally using `h = k`. Each step is valid because only the current maximum class exceeds `h`.

Verification against examples:
- `[5,2,5,4,5], k=2`: distinct > 2 = {5,4} → 2 ✓
- `[2,1,2], k=2`: min < k → -1 ✓
- `[9,7,5,3], k=1`: distinct > 1 = {9,7,5,3} → 4 ✓

Edge recheck: all elements already `k` → 0; single element `[5], k=3` → 1 (h=3 valid since only 5 exceeds it). Both consistent.

```python
class Solution:
    def minOperations(self, nums: List[int], k: int) -> int:
        if min(nums) < k:
            return -1
        return len({x for x in nums if x > k})
```
