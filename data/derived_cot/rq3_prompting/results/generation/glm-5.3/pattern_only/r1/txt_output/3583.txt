## Analysis

**Key constraints:** n up to 10⁵ (→ up to ~5×10⁹ pairs, can't enumerate), values up to 5×10⁴, 10⁵ queries.

**Chosen approach (classic GCD counting + Möbius-style inversion):**
- `cnt[g]` = number of elements divisible by `g` → pairs with gcd divisible by `g` is `C(cnt[g], 2)`.
- Going from `g = maxV` down to 1: `exact[g] = C(cnt[g],2) − Σ exact[m]` for multiples `m = 2g, 3g, …`. This is a harmonic-sum sieve, O(maxV log maxV).
- Prefix sums of `exact`, then answer each query with binary search (first `g` with cumulative count > query index).

**Invariant:** `exact[g]` equals the number of pairs whose gcd is exactly `g`, computed before it's needed by any divisor of `g` (descending order guarantees it).

**Edge cases checked:** all-ones array; `2g > maxV` (empty slice sums to 0); zero-count groups skipped via `if val`.

Verified against all three examples (e.g. example 2 → `exact = {1:3, 2:2, 4:1}`, prefix `[0,3,5,5,6]`, queries `[5,3,1,0]` → `[4,2,1,1]` ✓).
