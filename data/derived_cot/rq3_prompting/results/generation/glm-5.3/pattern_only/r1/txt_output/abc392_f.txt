**Approach (decided quickly):** The classic trick for "insert i at position P_i, in order, print final array" is to work **backwards over the final N slots**. Process i = N down to 1: element i's final slot is the P_i-th *still-empty* slot (proof: at insertion time, exactly P_i−1 of elements 1..i−1 precede i, and their relative order never changes, so # empty slots before i's final slot equals P_i−1). Find that slot with a Fenwick tree (all slots = 1, set to 0 when taken) using binary-lifting "find k-th one", then mark it filled. O(N log N).

Key details: pad the BIT to size = 2^⌈log₂N⌉ so the lifting needs no bounds checks; after the lifting loop, `pos` is already the 0-based result index. Verified by hand on both samples (n=4 → `4 2 3 1`, n=5 → `1 2 3 4 5`) including the tree updates each step; edge case n=1 traced correctly.

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    ps = list(map(int, data[1:1 + n]))

    log = n.bit_length()
    size = 1 << log
    tree = [0] * (size + 1)

    # Fenwick tree with 1 at positions 1..n (all slots initially empty)
    for i in range(1, n + 1):
        tree[i] += 1
        j = i + (i & -i)
        if j <= size:
            tree[j] += tree[i]

    # descending powers of two for binary lifting: size/2, ..., 1
    steps = [size >> k for k in range(1, log + 1)]

    res = [0] * n
    idx = n
    for p in reversed(ps):
        # find the p-th empty slot (k-th one in BIT)
        pos = 0
        for st in steps:
            c = tree[pos + st]
            if c < p:
                pos += st
                p -= c
        res[pos] = idx          # pos = final slot - 1 (0-based)
        j = pos + 1             # mark slot as filled
        while j <= size:
            tree[j] -= 1
            j += j & -j
        idx -= 1

    sys.stdout.write(' '.join(map(str, res)) + '\n')

main()
```
