class Solution:

Looking at this problem:

**Decisive constraints:** n ≤ 100, nums[i] ≤ 1000. Any O(n) or O(n²) approach works, but a prefix-sum solution gives a clean O(n).

**Plan (commit):** Build prefix sums where `prefix[k]` = sum of first k elements. For each index `i`, the subarray sum is `prefix[i+1] - prefix[start]` with `start = max(0, i - nums[i])`. Since `nums[i] ≥ 1`, `start ≤ i` always, so every subarray is valid and contains at least `nums[i]`.

**Ledger:**
- Invariant: `start = max(0, i - nums[i])` ∈ [0, i], subarray sum = `prefix[i+1] - prefix[start]`.
- Edge cases: single element (start=0, returns nums[0]); `nums[i] ≥ i` (start clamps to 0).

**Verify with Example 2:** nums = [3,1,1,2], prefix = [0,3,4,5,7]:
- i=0: start=0 → 3; i=1: start=0 → 4; i=2: start=1 → 2; i=3: start=1 → 4. Total = 13 ✓
