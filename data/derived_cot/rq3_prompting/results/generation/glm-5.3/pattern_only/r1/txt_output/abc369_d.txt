Takahashi will encounter N monsters in order. The i-th monster (1\leq i\leq N) has a strength of A_i.
For each monster, he can choose to either let it go or defeat it.
Each action awards him experience points as follows:

- If he lets a monster go, he gains 0 experience points.
- If he defeats a monster with strength X, he gains X experience points.
  If it is an even-numbered defeated monster (2nd, 4th, ...), he gains an additional X experience points.

Find the maximum total experience points he can gain from the N monsters.

Input

The input is given from Standard Input in the following format:
N
A_1 A_2 \ldots A_N

Output

Print the maximum total experience points he can gain from the N monsters as an integer.

Constraints


- 1\leq N\leq 2\times 10^5
- 1\leq A_i\leq 10^9
- All input values are integers.

Sample Input 1

28

## Approach

**Key constraint analysis:** The bonus for a defeated monster depends on its *position within the defeated sequence* (even positions get doubled). This creates a parity dependency between decisions, so a greedy approach is risky — a simple DP over (index, parity of defeated count) is the natural fit at O(N).

**DP formulation:**
- State: `e` = best XP after processing some prefix with an **even** number of defeats; `o` = best with an **odd** number of defeats.
- Transition for monster with strength `x`:
  - Defeat from odd count → count becomes even → gain `2x`: candidate for new `e` is `o + 2x`.
  - Defeat from even count → count becomes odd → gain `x`: candidate for new `o` is `e + x`.
  - Skipping keeps the current parity.
- Answer: `max(e, o)` at the end.

**Invariant check:** Defeating from state `o` gives doubled points (2nd, 4th, ... defeated monster) — matches the problem statement. Python big ints handle sums up to ~8×10¹⁴ safely.

**Verification on Sample 1** (`1 5 3 2 7`): states evolve (0,−∞) → (0,1) → (11,5) → (11,14) → (18,14) → (28,25), answer 28 ✓.
**Sample 2**: (0,−∞) → (0,10⁹) → (3·10⁹, 10⁹), answer 3·10⁹ ✓ (exceeds 32-bit, fine in Python).

**Edge cases:** N=1 → just `A_1` (no bonus, since 1st defeat is odd). Sentinel `NEG` can never win `max` since `e ≥ 0` always exists and the fake path stays deeply negative.

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    a = list(map(int, data[1:1 + n]))
    NEG = -(1 << 62)
    e, o = 0, NEG  # e: even #defeats so far, o: odd #defeats so far
    for x in a:
        e, o = max(e, o + 2 * x), max(o, e + x)
    print(max(e, o))

main()
```
