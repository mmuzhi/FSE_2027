=== ANSWER ===
## Approach

Let `p_i = (A_1 + ... + A_i) mod M` for `i = 0..N` (with `p_0 = 0`). For each subarray `[l, r]`:

```
(sum A_l..A_r) mod M = (p_r - p_{l-1}) mod M = p_r - p_{l-1} + M * [p_{l-1} > p_r]
```

since both values lie in `[0, M)`.

So the answer splits into two parts:
1. `sum over j < i of (p_i - p_j)` — computable incrementally with a running count and running sum of previous `p` values.
2. `M * (number of pairs j < i with p_j > p_i)` — a classic inversion count over values in `[0, M)`, done with a Fenwick tree (BIT) as we scan left to right.

Complexity: `O((N + M) log M)`.

**Verification on samples:**
- Sample 1: p = [0,2,3,3]; pair differences sum to 10, zero inversions → 10 ✓
- Sample 2: p = [0,20,98,42,46,91,30,86,43,99,39]; difference sum = 836, inversions = 19 → 836 + 1900 = 2736 ✓

Edge cases checked: `M = 1` (all zeros, answer 0), `N = 1` (answer `A_1 mod M`), all-zero array (answer 0). Python big ints handle the magnitude (~up to 4×10^15).

import sys

        cnt += 1
