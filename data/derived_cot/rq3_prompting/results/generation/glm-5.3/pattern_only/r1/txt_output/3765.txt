```python
class Solution:
    def minimumCost(self, nums: List[int], cost: List[int], k: int) -> int:
        n = len(nums)
        S = [0] * (n + 1)
        C = [0] * (n + 1)
        for i in range(n):
            S[i + 1] = S[i] + nums[i]
            C[i + 1] = C[i] + cost[i]
        totalC = C[n]
        INF = float('inf')
        dp = [INF] * (n + 1)
        dp[0] = 0
        # dp[j] = S[j]*C[j] + k*totalC + min_{l<j} (dp[l] - (S[j]+k)*C[l])
        for j in range(1, n + 1):
            x = S[j] + k
            base = S[j] * C[j] + k * totalC
            best = INF
            for l in range(j):
                v = dp[l] - x * C[l]
                if v < best:
                    best = v
            dp[j] = base + best
        return dp[n]
    ```

=== ANSWER ===
Looking at this problem:

- n ≤ 1000, so target is O(n²).
- Direct DP `dp[j][i]` (first j elements, i subarrays) would be O(n³) — too slow. The key trick: expand `k·i·W_i`. Since `Σ i·W_i = Σ_{t=1..m} (C[n] − C[l_t])` (each subarray starting at `l_t` contributes the cost-sum of everything from `l_t` to the end), the k-term becomes a **per-subarray constant** depending only on its left endpoint `l`.

So with prefix sums S (nums) and C (cost), a subarray `[l, j-1]` contributes exactly `S[j]·(C[j]−C[l]) + k·(C[n]−C[l])`, giving:

`dp[j] = S[j]·C[j] + k·C[n] + min_{l<j} (dp[l] − (S[j]+k)·C[l])`

Verified on Example 1 (dp[3] = 110: trace gives 28, 56, 110) and Example 2 (full trace yields dp[9] = 985), and algebraically on small cases (single subarray, splits).

Edge cases: n=1 gives `(nums[0]+k)·cost[0]` correctly; min over `l` is never empty for j≥1.

```python
from typing import List

class Solution:
```
