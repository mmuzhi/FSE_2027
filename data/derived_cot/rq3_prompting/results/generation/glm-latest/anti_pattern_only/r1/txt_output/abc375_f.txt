=== ANSWER ===
Looking at this problem:

- N ≤ 300 suggests all-pairs shortest paths (Floyd-Warshall).
- Deletions are hard, insertions are easy → process queries **offline in reverse**: start from the final state (roads still open at the end), and each "close road i" query becomes an "insert road i" query when traversed backwards.
- Adding a single edge (a,b,c) to a graph with correct APSP matrix `d` can be done in O(N²): `d'[u][v] = min(d[u][v], d[u][a]+c+d[b][v], d[u][b]+c+d[a][v])` — correct because a shortest path (non-negative weights) uses the new edge at most once, and the remaining segments are old-graph paths.
- With ≤ 300 insertions, total insertion cost is O(300·N²), fine with numpy vectorization.

Verified against both samples (traced by hand: sample 1 gives 10, 11, -1; sample 2 gives -1, -1, -1).

Implementation details:
- Initial APSP via numpy Floyd-Warshall (300 iterations of broadcasted min).
- Type-2 queries are batched between insertions for fast fancy indexing.
- INF = 2^60; unreachable entries stay exactly INF (all updates keep values ≤ INF since candidates involving INF exceed INF).
