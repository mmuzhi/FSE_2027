Looking at this problem:

- We need to compare multisets of A[l..r] and B[L..R] for each query.
- Values are bounded by N, so assign each value v ∈ [1,N] a random 96-bit integer h[v]. Then the multiset {A_l..A_r} has "signature" Σ h[A_i], which equals the signature of B's subsequence iff multisets match (with overwhelming probability, since a nonzero difference vector of counts sums to zero with probability ≤ 2^-96 per query; over 2·10^5 queries failure chance is ~2^-79).
- Use prefix sums of the hashed values for O(1) per query. Also check lengths match (deterministic and free).

Verification with samples:
- Sample 1: query 1 same multiset → Yes; query 2 lengths differ → No; query 3 multisets differ ({1,2,2,3} vs {1,2,3,4}) → No; query 4 identical multisets → Yes. ✓
- Sample 2: all handled correctly by length checks / equal hash sums. ✓

Complexity: O(N + Q) time. The random seed comes from `os.urandom`, so no adversarial fixed-seed attacks are possible.
