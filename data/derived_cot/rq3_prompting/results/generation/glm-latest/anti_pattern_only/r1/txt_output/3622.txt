class Solution:
    def maxFrequency(self, nums: List[int], k: int, numOperations: int) -> int:
        import bisect
        nums.sort()
        n = len(nums)
        candidates = set()
        for x in nums:
            candidates.add(x)
            candidates.add(x - k)
            candidates.add(x + k)
        ans = 0
        for T in candidates:
            # count of elements equal to T
            lo = bisect.bisect_left(nums, T)
            hi = bisect.bisect_right(nums, T)
            eq = hi - lo
            # count in [T - k, T + k]
            l2 = bisect.bisect_left(nums, T - k)

=== ANSWER ===
Looking at this problem:

- For a target value `T`, elements already equal to `T` count for free; each other element within distance `k` of `T` costs one operation to convert. Leftover operations can always be "wasted" by adding 0 to unused distinct indices (since `numOperations ≤ n`).
- So for a fixed `T`: `freq(T) = eq(T) + min(numOperations, cover(T) - eq(T))`, where `cover(T)` = count of elements in `[T-k, T+k]`.
- Which `T` to try? For any non-element `T`, moving `T` right to the nearest interval endpoint (some `nums[i] ± k`) never decreases coverage, and `freq ≥ min(cover, numOps)` there — so checking candidates `{nums[i]} ∪ {nums[i]-k} ∪ {nums[i]+k}` is sufficient. Element values are needed to capture duplicates (the `eq` term).

Verification with examples:
- `[1,4,5], k=1, ops=2`: `T=4` → eq=1, cover (in [3,5]) = 2 → 1+min(2,1)=2 ✓
- `[5,11,20,20], k=5, ops=1`: `T=20` → eq=2, cover (in [15,25]) = 2 → 2+min(1,0)=2 ✓

Edge cases: `k=0` or `numOperations=0` correctly reduces to max duplicate count; `t±k` may be negative/out of range — bisect handles that fine.

Complexity: sort `O(n log n)`, then ≤ `3n` candidates each with binary searches → `O(n log n)` overall, well within limits for `n = 10^5`.
