Looking at this problem:

- Binary search on the answer `x` (the minimum pairwise difference).
- Feasibility check: sort intervals by start. Any valid selection can be reordered so values follow sorted interval order (exchange argument). Then greedily pick the smallest allowed value `max(start[i], prev + x)` for each interval in sorted order; if it exceeds `start[i] + d`, `x` is infeasible.
- Upper bound for binary search: chosen values all lie within `[min_start, max_start + d]`, so the min gap is at most `(max_start - min_start + d) // (n-1)`.
