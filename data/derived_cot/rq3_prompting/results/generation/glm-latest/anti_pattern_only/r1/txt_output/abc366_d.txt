Looking at this problem:

- N ≤ 100, so the array has at most 100³ = 10⁶ elements.
- Q ≤ 2×10⁵ queries, so each query must be O(1).

**Approach**: Build a 3D prefix-sum array `P` of shape (N+1)³ with a zero border, where `P[x,y,z] = sum of A[1..x][1..y][1..z]`. Then each query is answered by inclusion-exclusion with 8 corner lookups:

```
P[Rx,Ry,Rz] - P[Lx-1,Ry,Rz] - P[Rx,Ly-1,Rz] - P[Rx,Ry,Lz-1]
+ P[Lx-1,Ly-1,Rz] + P[Lx-1,Ry,Lz-1] + P[Rx,Ly-1,Lz-1] - P[Lx-1,Ly-1,Lz-1]
```

For speed in Python, I use numpy: parse all tokens at once with `np.fromiter(map(int, tokens))`, compute prefix sums via chained `cumsum` along the three axes, and evaluate all queries vectorized with fancy indexing. Max values (~999×10⁶ ≈ 10⁹) fit comfortably in int64.
