import sys

def main():
    input_data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(input_data[idx]); idx += 1
    m = int(input_data[idx]); idx += 1
    
    parent = list(range(n + 1))
    size = [1] * (n + 1)
    
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]  # path halving
            x = parent[x]
        return x
    
    components = n
    
    for _ in range(m):
        u = int(input_data[idx]); idx += 1
        v = int(input_data[idx]); idx += 1
        ru, rv = find(u), find(v)
        if ru != rv:
            if size[ru] < size[rv]:
                ru, rv = rv, ru
            parent[rv] = ru
            size[ru] += size[rv]
            components -= 1
    
    print(m - (n - components))

main()

=== ANSWER ===
Looking at this problem:

**Key insight:** A forest on N vertices with c connected components has exactly N - c edges at maximum. For each connected component of the original graph with k vertices and e edges, we must delete at least e - (k - 1) edges (since any forest on those k vertices has at most k - 1 edges). This bound is achievable by keeping a spanning tree of each component.

Therefore the answer is **M - (N - c)**, where c is the number of connected components in the original graph.

**Verification with samples:**
- Sample 1: N=4, M=4, connected (c=1) → 4 - 3 = 1 ✓
- Sample 2: N=5, M=0, c=5 → 0 - 0 = 0 ✓
- Sample 3: N=10, M=10. Components: {1,2,4,5,6,7,8,9,10} and {3}, so c=2 → 10 - 8 = 2 ✓

**Implementation:** Use Union-Find (DSU) with path halving and union by size to count connected components. Start with N components; each union of two different roots decreases the count by 1. This runs in near O((N+M) α(N)) time, well within limits for N, M ≤ 2×10⁵.

The answer M - (N - c) is always non-negative since each connected component with k vertices has at least k - 1 edges.
