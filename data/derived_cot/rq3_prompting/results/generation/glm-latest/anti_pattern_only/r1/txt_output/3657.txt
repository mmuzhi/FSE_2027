=== ANSWER ===
Looking at this problem:

- Two horizontal cuts divide the grid into bottom/middle/top strips; two vertical cuts into left/middle/right strips.
- A cut at coordinate `c` is invalid for a rectangle spanning `[a, b]` only if `a < c < b` (cuts along rectangle edges are fine, as Example 1 confirms with cuts at y=2 and y=4 touching rectangle boundaries).
- So project rectangles onto one axis as intervals. We need two cut positions where no interval strictly crosses either, with each of the three sections containing at least one full interval.

**Approach:** Sort intervals by start. Sweep keeping a running maximum end (`cur_end`). Whenever an interval's start `s >= cur_end`, there is a genuine gap where a cut can be placed (all previous intervals end at or before `cur_end`, all future ones start at or after `s`). Count such separations; if we can form at least 3 separated blocks (2 gaps), valid cuts exist:

- *Sufficiency:* Place cut 1 at the max end of block 1 (≤ first start of block 2), cut 2 at max end of block 2. Then each block lies fully in its own section and no rectangle is crossed.
- *Necessity:* If valid cuts exist, rectangles in section 1 all end before section 2's rectangles start, which end before section 3's start — so in start-sorted order they appear as ordered groups, guaranteeing the sweep detects a gap at the first rectangle of section 2 and of section 3.

Check the x-projection (vertical cuts) and y-projection (horizontal cuts) independently. Complexity: O(m log m).

Verified against all three examples (Example 1: horizontal gives 3 blocks → true; Example 2: vertical gives 3 blocks → true; Example 3: both give only 2 blocks → false).

    def checkValidCuts(self, n: int, rectangles: List[List[int]]) -> bool:

            intervals.sort()
