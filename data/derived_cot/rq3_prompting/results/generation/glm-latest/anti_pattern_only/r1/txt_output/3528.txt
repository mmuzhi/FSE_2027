```python
class Solution:
    def findMaximumScore(self, nums: List[int]) -> int:
        total = 0
        cur_max = 0
        for p in range(len(nums) - 1):
            cur_max = max(cur_max, nums[p])
            total += cur_max
        return total
```

This is clean and O(n). Note constraints: n up to 1e5, nums[i] up to 1e5, so max total ~ 1e5 * 1e5 = 1e10, fits in Python int fine.

```python
class Solution:
    def findMaximumScore(self, nums: List[int]) -> int:
        total = 0

        return total
```

=== ANSWER ===
Looking at this problem:

- If we jump through stops `0 = i_0 < i_1 < ... < i_k = n-1`, each unit step from `p` to `p+1` is paid at rate `nums[i_t]` where `i_t` is the last stop `≤ p`.
- Upper bound: rate at step `p` can't exceed `max(nums[0..p])` since the stop determining it is at index `≤ p`.
- This bound is achievable by the greedy that stops at every position setting a new strict running maximum (then finally at `n-1`).

So the answer is `sum over p in [0, n-2] of max(nums[0..p])`.

Verification:
- `[1,3,1,5]`: prefix maxes `1,3,3` → sum `7` ✓
- `[4,3,1,3,2]`: prefix maxes `4,4,4,4` → sum `16` ✓
