import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    hs = list(map(int, data[1:1+n]))
    # extra[o][r], o = s % 3
    extra = [[0, 3, 4], [0, 1, 2], [0, 1, 4]]
    s = 1
    for h in hs:
        o = s % 3
        ex = extra[o]
        best = None
        for r in range(3):
            need = h - ex[r]
            if need <= 0:
                q = 0
            else:
                q = (need + 4) // 5
            m = 3 * q + r
            if best is None or m < best:
                best = m
        s += best
    print(s - 1)

main()

=== ANSWER ===
Looking at this problem:

- The k-th attack (T = k) deals 3 damage if k ≡ 0 (mod 3), else 1 damage.
- Enemies are attacked strictly in order; each enemy is attacked until its health drops to ≤ 0, then we move to the next. The process is fully deterministic.
- Since total attacks can be ~1.2×10¹⁴, we must compute, for each enemy in O(1), how many attacks it takes given its health H and the starting attack number s.

For an enemy starting at attack number s, let o = s % 3. In any 3 consecutive attacks the total damage is 5 (1+1+3), and the "extra" damage beyond full cycles for m = 3q + r attacks is:
- o = 0 (pattern 3,1,1): extra = [0, 3, 4]
- o = 1 (pattern 1,1,3): extra = [0, 1, 2]
- o = 2 (pattern 1,3,1): extra = [0, 1, 4]

So damage(m) = 5·(m//3) + extra[o][m%3], which is strictly increasing. For each residue r ∈ {0,1,2}, the minimal m ≡ r (mod 3) with damage ≥ H uses q = max(0, ceil((H − extra[r])/5)), giving m = 3q + r. Take the minimum over r; the next enemy starts at s + m. The answer is the final total attack count.

I verified this against all three samples (e.g., sample 1: enemy 1 takes 4 attacks, enemies 2 and 3 take 2 each → T = 8; sample 3: each enemy takes exactly 6×10⁸ attacks → 3×10⁹; sample 2 traces to 82304529).
