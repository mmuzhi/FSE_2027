```python
class Solution:
    def maxDistinctElements(self, nums: List[int], k: int) -> int:
        nums.sort()
        count = 0
        last = -10**18  # smaller than any possible assigned value
        for num in nums:
            target = max(last + 1, num - k)
            if target <= num + k:
                last = target
                count += 1
        return count
```

=== ANSWER ===
Looking at this problem:

- Each element can become any integer in `[num-k, num+k]` (staying unchanged = adding 0, which is allowed).
- We want to maximize the number of distinct final values, which is equivalent to finding the maximum set of elements that can be assigned **pairwise distinct** values from their ranges (any leftover element just duplicates an existing value and doesn't hurt).

**Greedy strategy:** Sort the array (this sorts both interval endpoints `[num-k, num+k]`). Process elements in order, assigning each the smallest possible value that is strictly greater than the last assigned value: `target = max(last + 1, num - k)`. If `target <= num + k`, the element gets a new distinct value; otherwise it can't contribute (it must duplicate something already used, which is unavoidable and optimal).

This "assign earliest feasible value" greedy is optimal because packing values as low and tight as possible leaves maximal room for later (larger) elements — a standard exchange argument applies since sorting makes both endpoints monotonic, so any skipped gap value is below the left endpoint of all remaining intervals.

**Verification with examples:**
- `[1,2,2,3,3,4], k=2` → assigns `-1, 0, 1, 2, 3, 4` → 6 ✓
- `[4,4,4,4], k=1` → assigns `3, 4, 5`, last one fails → 3 ✓
- `k=0` → reduces to counting distinct values ✓ (duplicates fail since `last+1 > num`)

Edge handling: initialize `last` to a value smaller than any possible assignment (`num-k ≥ 1 - 10^9`), e.g. `-(10**18)`. Complexity: O(n log n).
