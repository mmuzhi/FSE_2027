=== ANSWER ===
Looking at this problem:

- Replacing leftmost "WA" with "AC" turns the W into A and the A into C. The only new "WA" this can create is immediately to the left (if preceded by W), so the operation cascades leftward through the whole maximal block of W's preceding that A: `W^k A` → `A C^k`.
- Characters never become 'W', so whether a W-block gets converted depends only on the original string: a maximal W-block immediately followed by 'A' fully converts (first W→A, rest→C, and the A→C); a W-block followed by any other character (or end of string) stays unchanged forever.
- Similarly, an 'A' is consumed (becomes 'C') if and only if it is originally immediately preceded by a 'W'; otherwise it stays 'A'.
- Conversions happen strictly left to right and touch disjoint positions, so the final string can be computed in one linear scan with a counter of pending W's:
  - On 'W': count it.
  - On 'A' with pending W's: emit `'A' + 'C'*count`, reset.
  - On 'A' with no pending W's: emit 'A'.
  - On any other char (or end): flush pending W's as 'W'*count, then emit the char.
