Looking at this problem:

- Sort elements by A. For each threshold position i (prefix of i smallest-A elements, i ≥ K), the best choice taking max A = A_sorted[i] is to pick the K smallest B values within that prefix.
- Candidate answer = A_sorted[i] × (sum of K smallest B in prefix i). The overall answer is the minimum over all i ≥ K.
- Maintain sum of K smallest B values over the growing prefix using a max-heap of size K.

**Correctness sketch:** For any threshold m, any valid S with max A ≤ m has B-sum at least the K-smallest-B sum among elements with A ≤ m, so the optimum is ≥ the minimum candidate. Conversely, each candidate is achieved (or beaten) by an actual subset of the prefix, so the answer equals the minimum candidate.

Verified against all three sample cases (42, 60, 14579 — e.g., third case: prefix through A=61 gives B-set {30,39,30,16,76,48} sum 239, 61×239 = 14579).

Complexity: O(N log K) per test case, total O(sum N · log K), well within limits.

                if v < ans:
                    ans = v
        out.append(str(ans))
    sys.stdout.write('\n'.join(out) + '\n')

main()
