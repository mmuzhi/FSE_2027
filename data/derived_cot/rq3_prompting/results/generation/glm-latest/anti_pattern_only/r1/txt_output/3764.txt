Implementation:

```python
class Solution:
    def maxSum(self, grid: List[List[int]], limits: List[int], k: int) -> int:
        candidates = []
        for row, lim in zip(grid, limits):
            if lim > 0:
                # take top lim elements
                top = sorted(row, reverse=True)[:lim]
                candidates.extend(top)
        candidates.sort(reverse=True)
        return sum(candidates[:k])
```

Complexity: n*m log(m) for sorting each row + (n*m) log(n*m) for final sort. With n, m <= 500, that's 250,000 elements, sorting is fine.

```python
import heapq

class Solution:

        candidates = []
        for row, lim in zip(grid, limits):
            candidates.extend(heapq.nlargest(lim, row))
        return sum(heapq.nlargest(k, candidates))
```

=== ANSWER ===
```python
import heapq

class Solution:
    def maxSum(self, grid: List[List[int]], limits: List[int], k: int) -> int:
        candidates = []
        for row, lim in zip(grid, limits):
            if lim > 0:
                candidates.extend(heapq.nlargest(lim, row))
        return sum(heapq.nlargest(k, candidates))
```

**Approach:** Since all values are non-negative, from each row we should always consider its top `limits[i]` elements (taking fewer is never better). Collect all these candidates across rows, then take the overall top `k` of them for the maximum sum. Using `heapq.nlargest` keeps each row's selection efficient (O(m log limits[i])), and the final selection is O(total log k), which easily fits within constraints (n, m ≤ 500).

Verified against both examples: Example 1 gives 4+3=7, Example 2 gives 8+7+6=21. Edge cases like `k=0` or `limits[i]=0` naturally return empty selections summing to 0.
