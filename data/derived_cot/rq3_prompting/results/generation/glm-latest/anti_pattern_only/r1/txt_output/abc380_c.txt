Here is a more precise description.

- Let S_{l\ldots r} denote the substring of S from the l-th character through the r-th character.
- We define a substring S_{l\ldots r} of S to be a 1-block if it satisfies all of the following conditions:
- S_l = S_{l+1} = \cdots = S_r =  1
- l = 1 or S_{l-1} =  0
- r = N or S_{r+1} =  0

- T_i = S_i for 1 \leq i \leq r_{K-1}

- T_i =  0 for r_{K-1} + (r_K - l_K) + 2 \leq i \leq r_K
- T_i = S_i for r_K + 1 \leq i \leq N

Looking at this problem:

1. Find the first K 1-blocks (maximal runs of 1s) in S.
2. The K-th block spans `[lK, rK]` (0-indexed), and the (K-1)-th block ends at `rK1`.
3. The segment between positions `rK1+1` and `rK` gets rearranged: the ones of the K-th block (count = `rK - lK + 1`) move to the front of that segment, and the zeros (which were between the blocks) fill the rest.

So the result is: `S[:rK1+1] + '1'*ones + '0'*(rK - rK1 - ones) + S[rK+1:]`.

**Verification with Sample 1:** S = "010011100011001", K=3. Blocks (0-indexed): (1,1), (4,6), (10,11). lK=10, rK=11, rK1=6, ones=2. Result = "0100111" + "11" + "000" + "001" = "010011111000001" ✓

**Verification with Sample 2:** S = "1011111111", K=2. Blocks: (0,0), (1,9). lK=1, rK=9, rK1=0, ones=9. Result = "1" + "111111111" + "" + "" = "1111111110" ✓

Since blocks are maximal, there's always at least one 0 between consecutive blocks, so the zero count `rK - rK1 - ones` is always ≥ 0 (never negative). Using `str.find` in a loop keeps all scanning at C speed with total O(N) work since the search position only moves forward.
