**Reasoning:** The recursion consumes bits from the least-significant side (`n&1` picks the LSB) while building `r`. Therefore `n` must be shifted **right** (`n>>1`) to discard the consumed bit. The original `n<<1` shifts left, which never reduces `n` toward 0 (infinite recursion / `RecursionError`) and makes every subsequent `n&1` equal to 0. With `n>>1`, the base case `r<<(32-count)` correctly zero-pads the unprocessed leading zeros of the 32-bit input (e.g., `n=0` returns `0`, `n=43261596` returns `964176192`).
